# Soft-boundary loss 설계

**상태: 🟢 정본 (2026-08-21 개시, **§16으로 종결** -- 이후 갱신은 §17·§18 실측 추가뿐)**

> **결론만 필요하면 §16.4 한 표를 본다.** 한 문장: **더 좋은 모델을 주지 않고, 같은 모델을
> 더 일관되게 준다.** 정확도·안전 교환곡선은 CE와 같고, 살아남은 것은 **재학습 재현성
> 5~22배**(모든 τ에서)와 **되올림 2.4배 감소**다. `δ` 스윕 등 후속 손잡이는 §16.8에서 종결했다.
> **철회된 주장이 여러 개 있으니 옛 절의 σ를 그대로 인용하지 않는다**(§15.4·§16.2·§17).

> ## ⚠ [2026-09-02] **이 문서의 "왜"는 대조 실험으로 갱신됐다 -- [`loss_effect_results.md`](loss_effect_results.md)**
>
> 이 문서는 새 loss가 **무엇을 주는가**를 옛 config(`Y=1`, δ=0.15)에서 정리한 것이다.
> **무엇이 원인인가**는 `runs/loss_effect`의 25런(현재 config·정본 환경, 사다리 5칸)이
> 답했다. 핵심은 `C_hard` 대조군이다 -- 집계·가중치·δ가 전부 같고 **대역 target만 hard**인
> 칸의 되올림이 47.6 %로 CE(45.0 %)와 같고, target만 soft로 바꾸면 0.5 %가 된다.
> **즉 원인은 per-set 평균(§3.1)이 아니라 경계 대역의 hard 감독이다.**
> 그리고 CE의 val 오차 증가분의 **96.5 %가 경계 대역(셀의 12.7 %)에서** 온다.
>
> **§15·§16의 σ와 배율은 그 문서로 대체됐다** -- 옛 config·옛 환경의 값이고, 새 문서가
> 재현성 주장 셋을 철회했다(선택 epoch에서만 성립했다). 이 문서에서 인용 가능한 것은
> **설계와 수식, 그리고 기각 이력**이다.

## 1. 왜 이 loss인가 -- 한 문단 요약

현행 loss는 `valid` 셀 전체에 걸린 **가중 CE 하나**뿐이다. §26이 측정한 것은 val loss 증가분의
**89.7 %가 GT 경계 ±20 cm(4셀) 안**에서 나오고 **경계에서 먼 영역은 오히려 좋아진다**는 것이다.
그리고 그 증가의 2/3는 "더 확신하며 틀려서"다 -- ep40에서 놓친 free 셀에 주는 평균
`p(free)`가 **0.021**이다.

경계는 라벨이 신뢰할 수 없는 자리다. 데이터 수집 자체가 완벽하지 않았고 사람이 보정
annotation을 하면서 오차가 들어갔다(사용자 판단). **그런데 hard CE는 그 셀에도 `p→1`을
요구한다.** 그래서 라벨의 불완전성을 loss에 **명시적으로 모델링**한다: 신뢰할 수 있는
영역에는 지금과 같은 hard 목표를, 경계 근방에는 soft 목표를 쓴다.

```
L_BCE  =  L_region  +  L_soft-boundary
```

**두 항은 셀 집합이 겹치지 않는다.** 같은 셀에 두 항이 걸리는 형태가 아니라, 셀을 세 영역으로
나눠 각각 다른 항이 담당한다.

## 2. 기호와 영역 정의

### 2.1 부호 있는 수직 거리 `d_i` (**결정됨: 수직**)

- `Γ` -- GT free 영역의 경계.
- **`d_i^SDF`** -- 셀 중심 `x_i`에서 `Γ`까지의 **부호 있는 최단 거리** [m].

```
dist(x_i, Γ) = min_{q∈Γ} ‖x_i − q‖₂
d_i = + dist(x_i, Γ)   if x_i ∈ drivable
      − dist(x_i, Γ)   if x_i ∈ non-drivable
```

`d_i > 0`이면 drivable 쪽, `d_i < 0`이면 non-drivable 쪽이다.
구현은 `projects/common/soft_boundary.py:signed_distance_field`.

**왜 반경(광선 위) 거리가 아니라 수직 거리인가 -- 두 가지 이유가 있고 둘 다 실측/코드다.**

1. **판정 지표가 이미 수직 거리다.** `f1@τ`는 `occupied_metrics._distance_field_m`, 즉
   `distance_transform_edt(sampling=cell_m)`으로 정의된다 -- **같은 L2 거리 연산자, 같은 미터
   단위**다. 다른 것은 두 가지뿐이다: `f1@τ`는 부호 없이 **크기만** 쓰고, 대상 집합이 free
   영역 경계가 아니라 `occupied` 표면이다. **올리려는 지표와 loss가 같은 거리를 재는 것**이
   가장 강한 근거다.
2. **soft label의 근거가 "경계면이 공간상 몇 cm 밀릴 수 있다"이므로 재야 할 것이 법선 방향
   변위다.** 경계가 광선을 스치듯 지나가면(통로 측벽) 반경 거리는 크지만 수직 거리는 작다.
   즉 반경 정의는 **반경 위치가 가장 불확실한 셀에서 불확실성을 과소평가한다** -- 입사각
   `α`에서 유효 반경 불확실성이 `σ / cos α`로 커지기 때문이다.

**실측 대조(2026-08-21, `tools/measure_boundary_regions.py`, 267프레임 3.559 M셀).**

| δ=0.15 | `Ω_F` | `Ω_N` | `Ω_B` | `Ω_B` 셀당 계수 | B:N 배율 |
|---|---|---|---|---|---|
| 반경 | 19.33 % | 76.95 % | **3.72 %** | 13.44/\|V\| | **20.7×** |
| **수직(채택)** | 17.00 % | 73.33 % | **9.67 %** | 5.17/\|V\| | **7.6×** |

`δ = 0.15`에서 **Jaccard 0.305, 반경만 0.04 %, 유클리드만 11.02 %** -- 반경 대역은 수직
대역의 거의 순부분집합이고, **경계에서 15 cm 안인데 반경 정의가 hard 라벨로 넘기는 셀이
11 %** 있다. 그 11 %가 위 (2)의 스치는 측벽이다.

부수 효과로 `first_free_range`의 광선 상태 처리가 필요 없어진다 -- 참고로 실측에서
`RAY_NO_FREE`가 **45.28 %**(후방·측방 미관측), `RAY_OK` 41.73 %, `RAY_CENSORED` 12.99 %였다.
반경 정의를 골랐다면 광선 절반에 대한 특수 처리를 설계했어야 한다.

> **거리는 셀 중심 사이로 잰다.** 경계에 붙은 셀도 `|d| = cell_m = 0.05`이고 0이 되지 않는다
> (실제 경계면은 두 중심 사이, 약 0.025 m에 있다). 크기가 반 셀만큼 크게 나오지만 **양쪽에
> 대칭으로 걸리므로 target의 `y = 0.5` 교차점은 경계면에 그대로 남는다.** `δ = 0.15`면
> 대역이 한쪽에 3개 셀 껍질이고 target은 대역 안에서 약 6개 값만 취한다.

### 2.2 불확실 대역

**`δ = 0.15 m`**(= 3셀)으로 세 영역으로 나눈다.

| 영역 | 조건 | 뜻 | 담당 항 |
|---|---|---|---|
| `Ω_F` | `d_i > δ` | 확실한 drivable | `L_region` (hard) |
| `Ω_N` | `d_i < −δ` | 확실한 non-drivable | `L_region` (hard) |
| `Ω_B` | `|d_i| ≤ δ` | **uncertain boundary** | `L_soft-boundary` (soft) |

**세 집합은 서로 겹치지 않고 `permanent_blind ∪ invalid`를 뺀 나머지를 정확히 덮는다.**

`f1@10cm`의 허용 오차(2셀)가 이 대역 안이다. **실측 비율(δ=0.15, 수직 정의): `Ω_F` 17.00 %,
`Ω_N` 73.33 %, `Ω_B` 9.67 %.** §26의 밴드에서 loss 증가분의 89.7 %가 있던 폭은 0.2 m(4셀)이고
그때 대역은 15.86 %였다 -- `δ`를 0.15로 좁히면 대역이 9.67 %로 줄고 덮는 loss 몫도 그만큼
줄어든다. **이 교환비가 `δ` 스윕이 재는 것이다.**

### 2.3 채택되지 않은 반경 경로 (기록용)

반경 정의를 골랐다면 `R_gt(θ)`가 필요했고, 그것은 이미 구현되어 있다 --
`projects/common/polar.py:first_free_range`가 "첫 free 셀 이후 첫 non-free 셀까지의 거리"를
돌려준다(ego 아래 `permanent_blind` 원반을 건너뛰는 것이 그 함수의 계약이다). 셀→광선 대응과
부호 있는 반경 거리도 같은 모듈에 있다(`build_cell_ray_map`, `signed_boundary_distance`) --
`tools/measure_boundary_regions.py`가 두 정의를 대조하는 데 쓰므로 남겨 둔다.

**이 경로는 loss에 쓰지 않는다.** 위 §2.1의 두 근거 때문이다.

## 3. `L_region` -- 신뢰하는 영역의 hard BCE

**정의(사용자 설계).** `Ω_F`와 `Ω_N`에는 지금과 같은 hard BCE를 그대로 적용한다. 단
**각 영역에서 따로 평균을 낸 뒤 ½씩 더한다.**

```
L_F      = (1/|Ω_F|) · Σ_{i∈Ω_F} BCE(z_i, 1)
L_N      = (1/|Ω_N|) · Σ_{i∈Ω_N} BCE(z_i, 0)
L_region = ½ · L_F  +  ½ · L_N
```

**설계 의도(사용자).** `pos_weight`/역빈도 가중치를 **명시적 class balancing으로 대체**한다.
각 클래스에서 먼저 평균을 내면 셀 개수와 무관하게 두 클래스가 loss의 정확히 절반씩 기여한다.

### 3.1 이것이 현행 가중치와 무엇이 같고 무엇이 다른가

**같은 것: 균형의 수준이 1:1이라는 점.** 현행 역빈도 가중치도 이미 정확히 1:1이다. 현행 loss를
클래스별로 묶으면

```
L = λ_free · CE_free_mean + λ_notfree · CE_notfree_mean,   λ_c = w_c · (N_c / |V|)
```

이고 `w_c ∝ 1/N_c`이므로 그 곱이 상수가 된다. 현재 train split 실측:

| 클래스 | 비율 | `w_c` | `λ_c` |
|---|---|---|---|
| `free` | 20.37 % | 3.9092 | **0.7963** |
| `not_free` | 79.63 % | 1.0000 | **0.7963** |

소수 4자리까지 같고, 이것은 우연이 아니라 역빈도 가중치의 정의상 대수적으로 정확하다.
**따라서 ½/½ 결합은 "균형을 새로 잡는 것"이 아니다.**

**다른 것 -- 세 가지이고 모두 실질적이다.**

1. **배치마다 정확히 1:1이 된다.** 현행은 `w_c`가 전역 통계에서 고정되고 `N_c`·`|V|`는 배치마다
   달라서, 배치별 실효 `λ_c`가 흔들린다(free가 적게 들어온 배치에서는 free 항이 실제로 작아진다).
   per-class 평균은 배치 구성과 무관하게 정확히 ½이다. **데이터셋 통계에 대한 의존이 사라진다** --
   split을 바꿀 때 `class_weights_from_labels`를 다시 돌릴 필요가 없고, LOSO 7-fold에서 fold마다
   가중치가 달라지는 문제도 없어진다.
2. **셀당 계수가 줄어든다.** 현행 free 셀의 셀당 계수는 `w_free/|V| = 3.909/|V|`인데 새 형태는
   `½/|Ω_F|`다. 실측 `|Ω_F| = 0.170|V|`이므로 `2.94/|V|` (0.75×)이고, `Ω_N`은 `1.0 → 0.68/|V|`
   (0.68×)다. **균형은 그대로이고 실효 학습률이 내려간다** -- 단 `λ_B` 항이 더해지면 총
   gradient 스케일은 거의 회복된다(§4.4).
3. **분모가 `Ω`라서 경계 대역이 빠진 만큼 다시 정규화된다.** 현행 분모는 `|V|`(경계 포함)이고
   새 분모는 경계를 뺀 집합이다.

### 3.2 이 항이 무엇을 **잃는가** -- `L_soft-boundary`가 받아야 할 짐

`Ω_B`를 hard BCE에서 빼는 것은 §26의 측정 대상 그 자체를 제거하는 것이다. 경계 ±20 cm는
셀의 **15.86 %**이고 그 안에 오류의 대부분과 loss 증가분의 **89.7 %**가 있다. `δ = 0.15`면
**9.67 %**를 빼낸다. **즉 경계를 밀어 넣던 gradient의 상당 부분이 `L_region`에서는 사라진다.**

`L_soft-boundary`가 그것을 대신 공급하지 않으면 경계는 사실상 감독되지 않고, `Ω_F`/`Ω_N`의
압력으로 간접적으로만 정해진다. 결과는 두 방향 중 하나로 갈 수 있다.

- 경계가 자유롭게 흐물어져 `f1@10cm`이 더 나빠진다(감독 상실 -- §16이 binary 전환에서 이미
  −0.034를 이 원인에 귀속했다).
- 혹은 `Ω_F`/`Ω_N`의 압력만으로도 경계가 충분히 정해진다(대역이 한쪽에 3셀뿐이다).

**어느 쪽인지는 측정 문제이고, 그래서 `L_soft-boundary = 0`인 ablation을 반드시 같이 돌려야
한다** -- 그것이 "soft 항이 실제로 일을 하는가"의 유일한 답이다.

## 4. 미해결 구현 결정

여기 있는 항목은 **조용히 결정하면 안 되는 것들**이다. 각각 결과를 바꾼다.

### 4.1 `Ω_F`의 목표 -- **종결됨. 상수 1/0을 쓴다**

`L_F = BCE(z_i, 1)`은 "`d_i > δ` ⟹ 라벨이 free"를 가정한다. 실측에서 `Ω_F` 안의 non-free
셀은 **0.00 %**(수직 정의, 모든 `δ`)다. 수직 정의에서는 `d`의 부호가 곧 free 소속이므로
**정의상 그렇다** -- 그래서 "라벨 목표 대 기하 목표"라는 선택지 자체가 사라진다.
`Ω_N`의 free 오염도 0.00 %다.

(반경 정의였다면 0.01~0.02 %로 0이 아니었고, 그 경우 라벨을 목표로 쓰는 쪽이 맞았다.
수직 정의를 고른 부수 이득이다.)

구현은 `Ω_F`/`Ω_N`에서 라벨을 다시 읽지 않고 상수 1/0을 쓴다 -- 라벨을 읽어도 같은 값이고,
두 경로를 두면 나중에 갈릴 수 있다.

### 4.2 `permanent_blind` -- **종결됨. 분할에서 빼고 `Ω_N`에 넣는다**

앞서 "세 영역 어디에도 넣지 않고 통째로 제외"라고 적었는데 **그것은 틀렸다.** 두 요구를
동시에 만족해야 한다.

- **분할에서 빼야 한다.** 원반은 ego 근처라 경계에서 멀고 `d > δ`로 떨어진다. 그대로 두면
  라벨이 `unknown`(= not_free)인 셀이 `Ω_F`에 들어가 **free로 학습된다.**
- **그래도 감독해야 한다.** **지표는 `valid` 전체에서 채점되고 원반은 `valid`다**
  (`permanent_blind`는 `vis=0`을 강제하고 `valid`는 건드리지 않는다). 감독을 빼면 모델이
  원반에 free를 찍어도 loss가 벌하지 않는데 `fatal_rate`는 나빠진다. 정적이라 배우기 쉬운
  셀이므로 hard 목표 0으로 두는 것이 맞다.

따라서 `Ω_N = (valid & ~blind & d < −δ) | (valid & blind)`다.
구현·테스트: `soft_boundary.region_masks`,
`tests/common/test_soft_boundary.py::test_permanent_blind_is_merged_for_distance_but_not_for_supervision`.

거리장을 만들 때는 반대로 **원반을 free에 합친다** -- 합치지 않으면 원반 테두리가 경계로
잡혀 대역이 정적 마스크로 오염된다. 즉 원반은 **거리 계산에서는 free, 감독에서는 not_free**다.
이 비대칭이 의도된 것임을 여기 적어 둔다.

### 4.3 `δ`(그리고 `σ`)는 상수인가 거리 의존인가

`δ = 0.15 m`은 전 거리에서 같은 값이다. 그런데 불확실성의 물리적 원인은 거리에 따라 커진다 --
투영 오차와 ground-plane 가정 오차는 `r`에 대해 증가한다. §22가 이미 이것을 실측했다:
`rel_mae`(거리로 정규화한 오차)가 방위각에 대해 0.09–0.18로 평평했다. **즉 오차가 거리에
비례한다는 증거가 있다.** 그러면 `σ(r) = σ_0 + κ·r`(그리고 `δ = 3σ(r)`) 형태가 물리적으로
더 맞다. §5.2의 Gaussian 해석에서 `σ`가 물리량이므로 이 확장이 자연스럽게 붙는다.

상수로 시작해 값을 확정하고 거리 의존은 별도 ablation으로 둔다 -- 한 번에 두 손잡이를
바꾸면 어느 쪽이 효과를 냈는지 알 수 없다.

### 4.4 실효 학습률 -- `λ_B`가 더해지면 거의 해소된다

`L_region`만 보면 현행의 0.64×지만(§3.1), `λ_B·L_soft-boundary`가 더해지면 per-set 평균에
붙는 계수의 합이 `0.5 + 0.5 + 0.5 = 1.5`이고 현행은 `0.7963 × 2 = 1.593`이다.
**약 0.94×라서 실효 lr 보정은 거의 필요 없다.** (계수 합은 gradient 스케일의 근사치다 --
집합별 평균 loss가 다르므로 정확한 등가는 아니다.)

`λ_B`를 0.5에서 크게 움직이면 이 균형이 깨진다. **`λ_B` 스윕은 실효 lr 스윕을 겸한다는 것을
기록에 남긴다.**

### 4.5 성공 판정 기준 (미리 못박는다)

- **주 지표: `f1@10cm`** (현재 0.5478 ± 0.0017). 이 loss가 겨냥하는 것이 경계 정밀도다.
- 부지표: `fatal_rate`(0.1331 ± 0.0030), `free_miss_rate`, `iou_free`(0.7972 ± 0.0015).
- **`val_loss`를 기준으로 쓰면 안 된다.** σ가 0.0292로 `iou_free`의 20배이고(§24.1),
  더 근본적으로 **loss의 정의를 바꾸면 값이 비교 불가능해진다.**
- `iou_free`가 σ√2 = 0.0021보다 크게 떨어지지 않는 것을 제약으로 둔다.
- **`fatal`↓/`miss`↑ 드리프트를 멈추는 것 자체는 목표가 아니다.** §26.6(3) -- 지금 드리프트는
  안전한 방향이다. 경계를 대칭으로 부드럽게 하면 이 드리프트도 멈추는데, 그것이 바람직한지는
  별도 결정이다(비대칭 soft 목표로 유지할 수도 있다).

## 5. `L_soft-boundary` -- 경계 대역의 soft target BCE

**정의(사용자 설계).** `Ω_B = {i : |d_i| ≤ δ}`의 셀만 대상이고, **핵심은 target을 0/1로 자르지
않는 것**이다. BCE 자체는 그대로 쓰고 target만 `[0, 1]`의 연속값이 된다.

```
L_soft-boundary = (1/|Ω_B|) · Σ_{i∈Ω_B} BCE(z_i, y_i^soft)
```

전체 loss는 대역 항에 하이퍼파라미터 가중치를 붙여 결합한다.

```
L_BCE = L_region + λ_B · L_soft-boundary,        λ_B = 0.5 (초기값)
```

### 5.1 선형 soft target (기준선)

```
y_i^soft = ½ · (1 + d_i/δ)
```

`d = +δ` → 1, `d = 0` → 0.5, `d = −δ` → 0. **`L_region`의 hard 목표와 대역 끝에서 정확히
이어진다**(연속). 구현이 가장 단순하고, 아래 CDF 형태의 대조군으로 반드시 남겨야 한다.

### 5.2 Gaussian CDF soft target -- 물리적 유도가 있다

```
y_i^soft = Φ(d_i / σ)
```

transition이 S-curve가 되고, **`σ`가 "경계를 얼마나 모르는가"라는 물리량**이 되어 해석
가능한 하이퍼파라미터가 된다(선형식의 `δ`에는 그런 뜻이 없다 -- 단지 자르는 폭이다).

**유도(사용자 제시, 검증 완료).** GT 경계가 `R_true = R_gt + ε`, `ε ~ N(0, σ²)`로 흔들린다고
가정하면

```
P(cell i가 실제로 drivable) = P(r_i < R_true) = P(r_i < R_gt + ε)
                            = P(ε > r_i − R_gt) = P(ε > −d_i)
                            = P(ε < d_i)                     (ε 대칭)
                            = Φ(d_i / σ)
```

즉 soft target은 임의의 완화가 아니라 **경계 위치의 불확실성을 명시적으로 모델링한 사후확률**
이다. 이것이 이 설계의 핵심 논거이고 논문에서 쓸 수 있는 형태다.

### 5.3 plain `Φ(d/σ)`는 `L_region`과 불연속이다 -- 절단 정규로 고친다

`Φ`는 유한 구간에서 0/1에 도달하지 않으므로 대역 끝에서 목표가 튄다: `σ = δ/2`면
`Φ(2) = 0.977`, `σ = δ`면 `Φ(1) = 0.841`인데 바로 옆 `Ω_F` 셀의 목표는 1.0이다.
**불연속의 위치가 임의로 고른 `δ`라는 것이 문제다.**

권장 형태는 **대역 안에서 정규화한 CDF**다.

```
y_i^soft = ( Φ(d_i/σ) − Φ(−δ/σ) ) / ( Φ(δ/σ) − Φ(−δ/σ) )
```

이것은 편법이 아니라 **"오차가 ±δ 안에 있다는 것은 안다"는 절단 정규 사전분포에서의 정확한
사후확률**이다. §5.2의 물리적 해석을 유지하면서 `δ`와 `σ`를 독립 손잡이로 되돌린다.

대안: **`δ = 3σ`로 묶는다.** `Φ(3) = 0.9987`이라 불연속이 0.0013으로 무시 가능해지고 손잡이가
하나로 줄어든다. `δ = 0.15`면 `σ = 0.05 m`(1셀)인데, **수동 annotation 오차가 1셀이라는 것은
낙관적**일 수 있다 -- 그래서 정규화 형태가 더 안전하다.

### 5.4 soft target BCE는 0으로 내려가지 않는다 -- `KL`을 로그해야 한다

target이 모델과 무관한 상수이므로 최소값은 `p_i = y_i`에서의 **target 엔트로피** `H(y_i)`다.
선형 target이면 `y`가 `[0, 1]`에 균일하므로 `∫₀¹ H(y) dy = 0.5` nats이고, `λ_B = 0.5`를
곱하면 **전체 loss에 상수 0.25가 얹힌다.**

**이것이 실무적으로 중요하다.**

1. **loss 값이 현행과 비교 불가능해진다.** §4.5가 `val_loss`를 판정 기준에서 뺀 이유가
   여기서 한 번 더 강해진다.
2. **"수렴하지 않는" 것처럼 보인다.** 하한에 붙어 평평해지는 것을 실패로 오독할 수 있다.
   이 프로젝트는 §17에서 이미 같은 종류의 오독을 한 번 했다.
3. 대책: **`KL = L_soft-boundary − H̄`를 같이 로그한다**(`H̄`는 배치의 실제 target에서 계산).
   최적점에서 0으로 가므로 **경계 항의 진짜 진행도는 이 값으로만 읽힌다.**

### 5.5 이 항은 결정 경계를 흐리지 않는다 -- 확신만 흐린다

§3.2에서 우려한 "경계 감독 상실"에 대한 답이다.

- 최적점이 `p_i = y_i`이고 `y`는 `d`에 대해 **단조**이며 `y = 0.5 ⟺ d = 0`이다.
- 따라서 **`argmax`(문턱 `p = 0.5`)가 정확히 GT 경계 `d = 0`에 놓인다.**
- 즉 soft target은 `f1@10cm`·`iou_free`가 재는 **결정 위치를 옮기지 않고**, 그 위치에서의
  **확신만** 0.5로 내린다. 이 설계가 이 점에서 정확히 맞다.

감독도 실제로 공급된다. §26.3의 병리를 예로 들면 ep40에서 놓친 free 셀의 `p(free)`가 0.021인데,
`d = +0.1`(`δ = 0.15`) 셀의 목표는 0.83이므로 gradient `p − y = −0.81`이 크게 걸린다.

**그래도 `λ_B = 0` ablation은 돌려야 한다** -- 위는 원리이고, 대역이 3셀뿐일 때 실제로 얼마나
기여하는지는 측정 문제다.

### 5.6 `λ_B = 0.5`는 경계 셀에 가장 큰 셀당 가중치를 준다

세 항이 모두 per-set 평균이므로 셀당 계수는 `계수/|Ω|`다. **실측(δ=0.15, 수직 정의):**

| 집합 | 셀 비율 | 셀당 계수 |
|---|---|---|
| `Ω_F` | 17.00 % | 2.94/\|V\| |
| `Ω_N` | 73.33 % | 0.68/\|V\| |
| **`Ω_B`** | **9.67 %** | **5.17/\|V\|** |
| (현행 `free`) | 20.37 % | 3.91/\|V\| |
| (현행 `not_free`) | 79.63 % | 1.00/\|V\| |

**경계 셀이 `Ω_N` 셀의 7.6배를 받는다.** 의도된 배분일 수 있지만 `λ_B = 0.5`라는 숫자만 보면
드러나지 않으므로 명시한다. 반경 정의였다면 `Ω_B`가 3.72 %라 같은 `λ_B`로 **20.7배**가 됐다 --
**`λ_B`의 뜻이 `d_i` 정의와 `δ`에 함께 걸려 있다**는 뜻이고, 그래서 `λ_B`를 스윕할 때 이 표를
항상 같이 기록해야 한다.

`compute_soft_boundary_loss`가 `share_*`(항의 loss 기여 몫)와 `frac_*`(셀 비율)을 함께
돌려주는 이유가 이것이다.

### 5.7 지표는 hard 라벨로 계속 채점한다 -- 의도적이다

`iou_free`·`f1@10cm`·`fatal_rate`·`free_miss_rate`는 **0/1 라벨 그대로** 재야 한다.
지표까지 soft로 만들면 **우리의 가정으로 우리를 채점**하는 것이 되어, 개선인지 가정인지
구별할 수 없다.

**loss와 지표가 `Ω_B`에서 서로 다른 말을 하는 것은 결함이 아니라 설계다.** 나중에
"불일치"로 보고 고치지 않도록 여기 박아 둔다.

## 8. 실행 방법

```bash
# soft-boundary (선형, 기본값 δ=0.15 λ_B=0.5)
LOSS=soft_boundary bash configs/train_robot_bev_finetune.sh

# "soft 항이 일을 하는가" ablation
LOSS=soft_boundary LAMBDA_B=0.0 bash configs/train_robot_bev_finetune.sh

# Gaussian target
LOSS=soft_boundary SOFT_TARGET=gaussian SIGMA_M=0.08 bash configs/train_robot_bev_finetune.sh

# 대조군 (현행 역빈도 가중 CE)
bash configs/train_robot_bev_finetune.sh
```

`LOSS=soft_boundary`는 `FORMULATION=binary`에서만 동작한다(다른 조합은 즉시 실패한다) --
부호 있는 거리 하나로 영역을 나누는 유도가 2-class를 전제하기 때문이다.

**`λ_B = 0`으로 둬도 `loss_boundary`와 `kl_boundary`는 계속 로그된다.** 즉 ablation 런은
**경계 대역을 감독하지 않으면서 그 대역이 얼마나 틀리는지 관측한다** -- 두 런의 `kl_boundary`
곡선을 나란히 놓으면 soft 항의 효과가 직접 보인다.

### 로그에서 무엇을 볼 것인가

| 항 | 뜻 |
|---|---|
| `loss_free` / `loss_not_free` | `Ω_F` / `Ω_N`의 hard BCE 평균 |
| `loss_boundary` | `Ω_B`의 soft BCE 평균. **0으로 가지 않는다** (하한 = target 엔트로피) |
| **`kl_boundary`** | **경계 항의 진짜 진행도.** 최적점에서 0 |
| `share_nf/f/b` | 각 항의 총 loss 기여 몫 (합 1) |
| `bnd_kl몫` | 상수 하한을 뺀 **축소 가능한** loss 중 경계 항의 몫. `share b`보다 작다 |
| `frac_*` | 세 영역의 셀 비율 |

첫 스모크 실측(2 epoch, raws2+raws3 → raws1): `share b`가 0.67~0.74인데 `bnd_kl몫`은 그
절반 남짓이었다. **`share b`만 보면 경계 항의 영향력을 과대평가한다** -- 그 항에 들어 있는
엔트로피 하한은 상수여서 gradient가 0이기 때문이다.

## 7. `δ`·`λ_B`·`σ`는 라벨에서 정할 수 없다 (실측으로 확인)

**중요하고 반직관적이라 따로 적는다.** `P(label = free | d)`를 0.025 m 빈으로 실측했더니
**완벽한 계단**이었다.

| `d` 구간 [m] | 수직 정의 `P(free)` |
|---|---|
| −0.10 ~ −0.075 | **0.000** |
| −0.025 ~ 0 | **0.000** |
| +0.025 ~ +0.05 | **1.000** |
| +0.10 ~ +0.125 | **1.000** |

당연하다 -- `d`가 라벨에서 유도된 양이라 라벨은 `d`의 부호에 대해 **결정론적**이다.
(반경 정의에서 보이던 2~9 %의 흐림은 광선/셀 이산화 잡음이고 라벨 불확실성이 아니다.)

**따라서 `σ`를 라벨에 적합시키는 것은 원리적으로 불가능하다. 적합할 분포가 없다.**
`δ`·`λ_B`·`σ`는 전부 **우리가 주장하는 사전분포**이고 측정치가 아니다.
**논문에 "라벨에서 σ를 추정했다"고 쓰면 틀린 주장이 된다.**

정하는 방법은 이것뿐이다.

- **`δ`, `λ_B`** -- validation 스윕. 데이터가 주는 제약은 `δ`의 하한 하나뿐이다(격자 양자화
  1셀 = 0.05 m보다는 커야 한다). `λ_B`는 `δ`와 `d_i` 정의에 뜻이 걸려 있으므로 §5.6의 표를
  같이 기록한다.
- **`σ`** -- 스윕이 기본이지만, **일부 프레임을 재annotation해서 편차를 재면 하이퍼파라미터가
  아니라 측정량이 된다.** 20프레임 정도로 충분하고, 그러면 "라벨 불확실성을 측정해 loss에
  넣었다"는 훨씬 강한 주장이 된다. 사용자 시간이 유일한 비용이다. 대안은 시간적 일관성
  (연속 프레임을 ego-motion 보정해 비교 -- 하한만)과 캘리브레이션 오차 예산(상한만)이다.

스윕은 val split에 대한 선택이므로 진단 §25.2의 선택 편향이 걸린다. **config 동결을 튜닝 후에
선언하기로 한 결정이 그래서 맞고, 스윕 조합 수를 적게 유지하고 무엇을 봤는지 기록해야 한다.**

1. **대역은 시각 증거가 가장 약한 자리다.** train KL을 내리는 유일한 길이 암기다.
2. **gradient가 거기 몰려 있다.** 7.65 % 셀에 68 %. → **손잡이로 희석 가능**하고 실제로 들었다.
3. **soft target도 라벨의 결정론적 함수다.** 확신은 부드럽게 했지만 **위치는 못박았다.**

   놓인 램프를 재현하라고 요구받는다. **따라서 완벽한 모델도 val KL이 0이 될 수 없다.**

(3)의 증거: 정상 거동이라면 val KL이 하한까지 내려가서 **머물러야** 하는데, 실제로는 ep2~7에
최저를 찍고 바로 오른다. 즉 하한을 지나쳐 암기로 넘어간 것이다.

## 10. α = σ/δ -- 모양 축의 분리와 2차 스윕

### 10.1 왜 σ가 아니라 α인가

정규화된 target에 `u = d/δ`를 넣으면

```
y = (Φ(u/α) − Φ(−1/α)) / (Φ(1/α) − Φ(−1/α)),        α = σ/δ
```

가 되어 **`δ`가 식에서 사라진다.** 즉

- **`δ` = 대역 폭** -- 몇 개 셀이 soft가 되나 → gradient 희석 → **수렴**
- **`α` = 모양** -- 전이가 얼마나 날카로운가 → **경계 정밀도**

**두 손잡이가 직교한다.** σ를 미터로 주면 `δ`를 바꿀 때 모양이 조용히 같이 바뀌고, 그러면
"폭을 넓힌 효과"와 "모양을 둔하게 한 효과"가 섞인다 -- **1차 스윕의 δ=0.10 대 0.15 비교가
실제로 그 오염을 안고 있었다.** 테스트가 이 성질을 고정한다
(`test_alpha_makes_the_shape_independent_of_delta`).

**두 극단이 모두 알려진 loss다.**

```
α → 0   :  hard step        (soft label의 의미가 사라진다)
α → ∞   :  정확히 선형 target  (Φ(x) ≈ 0.5 + φ(0)x로 전개하면 ½(1 + d/δ))
```

**즉 선형은 별도 형태가 아니라 이 계열의 한쪽 끝이다.** 1차 스윕의 선형 런들은 α 축의
`α = ∞` 점이다.

### 10.2 격자 양자화가 α의 하한을 만든다

5 cm 격자에서 셀 중심의 최소 `|d|`가 **1셀**이다(`d = 0`에 셀이 없다). δ=0.15에서 셀이 실제로
놓이는 `|d|`는 `{0.05, 0.071, 0.10, 0.112, 0.141, 0.15}`뿐이다.

| α | σ | 최근접 셀(1셀)의 target | 중앙 기울기 |
|---|---|---|---|
| 0.15 | 0.45셀 | **0.987** | 17.7/m ← **사실상 hard** |
| 0.25 | 0.75셀 | 0.909 | 10.6/m |
| 0.33 | 1.00셀 | 0.842 | 8.0/m |
| 0.50 | 1.50셀 | 0.759 | 5.6/m |
| 1.00 | 3.00셀 | 0.691 | 3.9/m |
| ∞ | - | 0.667 | 3.3/m |

**α ≲ 0.2는 우리 격자에서 의미가 없다** -- 셀이 있는 자리에서 target이 이미 1.0에 붙어
soft target이 이름만 남는다.

### 10.3 2차 스윕 결과 -- α는 깨끗한 단일 교환 축이다

> **[2026-08-23 기각] "깨끗한 단일 교환 축"은 노이즈였다.** 아래 `f1@10cm` 5점의 인접 간격이
> 0.002~0.004인데 실측 σ_run이 0.0037이다(§13.6.1). 단조 순서는 주장할 수 없다. 되올림 쪽
> 순서(+13.9 ~ +43.8 %)는 σ 0.53pp이므로 그대로 유효하다.

`configs/sweep_soft_alpha.sh`, δ=0.15·λ_B=0.5 고정.

| α | 중앙 기울기 | `f1@10cm`@40 | 되올림 | val kl |
|---|---|---|---|---|
| 0.25 | 10.6/m | **0.5521** | +43.8 % | 1.103 |
| 0.33 | 8.0/m | 0.5502 | +30.5 % | 0.902 |
| 0.50 | 5.6/m | 0.5491 | +16.5 % | 0.708 |
| 1.00 | 3.9/m | 0.5470 | +13.9 % | 0.611 |
| ∞ (선형) | 3.3/m | 0.5430 | +14.6 % | 0.593 |

**`f1@10cm`이 α에 대해 단조**(0.5430 → 0.5470 → 0.5491 → 0.5502 → 0.5521)이고 되올림도
같이 오른다. 즉 α는 **성능↔수렴의 깨끗한 단일 교환 축**이다.

**선형이 Gaussian에 지배된다.** α=1.0이 선형과 같은 되올림(+13.9 % 대 +14.6 %)에서
`f1@10cm`을 **+0.0040** 더 낸다. **최종 선택은 Gaussian이어야 한다** -- "선형을 먼저"라는
§5.1의 권고는 검증 순서로는 옳았지만 최종 선택으로는 틀렸다.

### 10.4 `λ_B`는 이미 좋은 값이다

α=0.5 고정, `λ_B` 0.5 → 0.25:

| λ_B | `f1@10cm` | 되올림 | val kl |
|---|---|---|---|
| 0.50 | **0.5491** | +16.5 % | 0.708 |
| 0.25 | 0.5445 | +14.8 % | **0.747** |

f1이 −0.0046 떨어지는데 되올림은 −1.7pp만 좋아지고 **val kl은 오히려 나빠진다.**
감독을 약하게 하니 경계가 더 틀린다. **지배된다 -- `λ_B = 0.5`를 유지한다.**

### 11.1 확정 (논문에 쓸 수 있는 것)

**(1) 새 loss가 역빈도 가중 CE를 이긴다.**

> **[2026-08-23 주장 교체] 이 항목의 근거는 `f1@10cm`이 아니라 안전 지표와 수렴이다.**
> §13.6.1이 σ_run을 실측한 뒤 전 지표를 다시 읽었더니(§13.7) `f1`·`iou_free`는 **전부
> 노이즈 안**이고, 실제로 움직인 것은 `fatal_rate`(−5.2 %, 14σ),
> `missed_obstacle`(−11.5 %, 8.4σ), `range_bias`(−13 %, 4σ), 되올림(−74 %, 94σ)이었다.
> 아래 표의 `f1@10cm` 열은 그대로 두지만 **판정 근거로 쓰지 않는다** -- 대체 주장은 §13.7.2다.

같은 split·같은 시드·같은 고정 epoch에서

| | `f1@10cm` | `fatal` | `iou_free` | 되올림 |
|---|---|---|---|---|
| `ce` (가중 CE) | 0.5458 | 0.1331 | 0.7967 | +66.7 % |
| 성능 우선 (δ0.10) | **0.5561** (+0.0103, 6σ) | **0.1251** (−0.0080) | 0.7976 | +36.6 % |
| 수렴 우선 (α1.0) | 0.5470 | 0.1268 | **0.7984** | **+13.9 %** (1/4.8) |

`iou_free`가 노이즈 안(±0.0015)에서 움직이는 것이 **의도한 모양**이다 -- 이 loss가 겨냥한
것은 면적이 아니라 경계 정밀도이고, 정확히 거기서만 움직였다.

**(2) 경계 감독은 필수다.** `λ_B = 0`으로 대역을 loss에서 빼면 `f1@10cm`이
δ=0.10에서 **−0.046**, δ=0.15에서 **−0.113** 무너진다. train `iou`도 0.99 → 0.87로 떨어져
**train에서조차 경계를 맞추지 못한다.** 즉 `Ω_F`/`Ω_N`의 간접 압력만으로는 경계가 정해지지
않는다(§3.2의 두 갈래 중 "감독 상실" 쪽이 확정).

**(3) "전부 hard"는 최적이 아니다.** `ce`는 교환 곡선에서 **지배된다** -- 되올림 +66.7 %에
`f1@10cm` 0.5458로, 프론티어의 거의 모든 점보다 나쁘다. **soft가 필요하다는 근거가 실측이다.**

**(4) 선형보다 Gaussian이다** (§10.3).

**(5) 발산의 위치가 특정됐다.** val loss 상승분의 **126 %가 경계 항**이고, 그 항은 전 설정에서
train/val KL이 **28~42배** 벌어진다. 정성적 관찰("loss가 안 떨어진다")이 **하나의 항, 셀의
7~10 %**로 좁혀졌다.

### 11.2 기각 -- 세 손잡이 모두 같은 곡선 위를 움직인다

`δ`↓, `α`↓, `λ_B`↑는 전부 "경계를 더 세게 감독" 방향이고 **`f1@10cm`↑ & 되올림↑**이다.
**어느 손잡이도 프론티어를 옮기지 못했다.**

교환 곡선(ep40, `λ_B`=0.5 계열):

| 되올림 | `f1@10cm` | 설정 |
|---|---|---|
| +13.9 % | 0.5470 | δ0.15, α1.0 |
| +16.5 % | 0.5491 | δ0.15, α0.5 |
| +30.5 % | 0.5502 | δ0.15, α0.33 |
| +36.6 % | **0.5561** | δ0.10, α∞ |
| +43.8 % | 0.5521 | δ0.15, α0.25 (지배됨) |
| +66.7 % | 0.5458 | `ce` (지배됨) |

되올림을 4.8배 줄이는 대가가 `f1@10cm` −0.0091이다. **"성능 최대 + 수렴"은 손잡이로
얻을 수 없다.**

### 11.3 이 세션에서 내가 틀렸던 판단 (다음 세션이 반복하지 않도록)

| 주장 | 왜 틀렸나 |
|---|---|
| "선형을 최종으로 써도 된다" | Gaussian에 지배된다(§10.3) |
| "α=1.0은 정보량이 낮다" | α=1.0이 선형을 두 축 모두에서 이겼다 -- 프론티어 점이다 |
| "α↓는 δ↓보다 비효율적이다" | ep40 규약의 산물이었다. ep25에서는 α=0.25가 δ=0.10을 f1에서 이긴다 |
| "고정 epoch 40이 soft에 불리하다" | 설정마다 방향이 다르다. `sb_d10_lb50`은 ep40이 더 좋다 |
| "`permanent_blind`를 세 영역에서 통째로 제외한다" | 지표가 `valid` 전체에서 채점되므로 감독을 빼면 `fatal`이 나빠진다. **거리 계산에서는 free에 합치고 감독은 hard `Ω_N`**이 맞다(§4.2) |

### 11.4 고정 epoch은 40으로 유지한다 (사용자 결정)

ep25로 옮기면 soft 런은 최대 +0.0071 이득, `ce`는 −0.0116 손실이라 **대조군 대비 우위가
커진다**(+0.0103 → +0.0249). 그런데도 40을 유지하는 이유는 **`iou_free`가 ep25→40에서
계속 개선되는 구간**이기 때문이다(`ce` 0.7915 → 0.7967). 즉 **현재 비교는 대조군에 유리한
쪽으로 보수적이다** -- 논문에서는 그 점을 밝히는 것이 유리하다.

## 12. 다음 세션 -- 보조 loss 두 개를 검증한다

**상태: soft 방식이 CE보다 낫다는 것은 확정. 남은 것은 "성능 최대 + 수렴"을 동시에 얻는 것.**
§11.2가 손잡이로는 불가능하다고 실측했으므로, **항을 추가해야 한다.**

### 12.1 (사용자 계획) 거리 기반 보조 loss

경계까지의 **거리** 자체를 회귀 신호로 쓴다. 현행 지표에 이미 대응물이 있다 --
`range_mae`(방위각별 first-non-free 거리 오차, 현재 0.235 m)와 `f1@τ`.

설계할 때 정해야 할 것:
- 무엇을 회귀하나: 방위각별 거리 `R(θ)` (M3의 미분 가능한 짝) 대 per-cell 거리장 `d`
- **`d_bev_g`는 이미 배치에 들어 있다**(§6 구현 상태) -- per-cell 거리장 회귀는 추가 데이터
  파이프라인 없이 바로 붙는다
- 어느 셀에 걸 것인가: 대역 안만 대 전체
- 가중치와, 그것이 `λ_B`와 어떻게 상호작용하는가

### 12.2 (에이전트 제안) 허용오차 F1 항

**§9.5의 원인 (3)을 직접 겨냥하는 유일한 항이다.** 지금 loss는 "경계가 정확히 이 셀에
있다"고 가르치므로 라벨의 위치 오차까지 암기한다. 대신 **"경계가 τ 안에 있으면 정답"** 으로
가르치면 τ 안의 변위에 대해 loss가 **평평**해져 **암기할 대상이 없어진다.**

```
pred_dil = max_pool2d(pred_boundary, τ)      # 미분 가능한 팽창
gt_dil   = max_pool2d(gt_boundary,  τ)
L_tol    = 1 − soft_F1(pred ∩ gt_dil, gt ∩ pred_dil)
```

부수 이득: **주 지표 `f1@10cm`의 미분 가능한 대리**이므로 loss와 지표가 같은 것을 잰다.

**검증 예측:** train/val KL 격차(현재 28~42배)가 줄고 val 곡선이 **내려가서 머문다.**
그렇게 되면 프론티어가 옮겨진 것이다.

**안 되면 그것도 결과다.** 손잡이 3개와 항 2개를 다 시도하고 경계에서 멈춘다는 것은
§26.5의 "경계의 환원 불가능한 불확실성(라벨 정밀도 + 기하)"에 대한 강한 근거가 된다.

### 12.3 그 뒤 순서

1. 두 항을 각각, 그리고 함께 스윕 → **loss 최종 확정**
2. **시드 3~5개** (사용자 결정으로 여기까지 미뤄뒀다). `ce`의 σ를 빌려 쓰는 상태를 끝내고
   soft loss 자신의 σ를 측정한다
3. **config 동결 선언** → LOSO 7-fold × 3시드 (진단 §25.3)
4. 승자 체크포인트 재생성(8분) → **§26 밴드 분해 재측정**. 스칼라가 좋아졌다는 것보다
   **오차 구조가 바뀌었다**는 것이 논문에서 훨씬 강한 근거다
5. 정성 비교 영상 -- 이 논의의 출발점이 "정량은 나쁜데 정성은 좋다"였고, 그 간극이 줄었는지는
   영상으로만 보인다

### 12.4 선택 사항 -- α를 측정량으로 만들기

`α`(즉 `σ`)는 지금 하이퍼파라미터다. **20프레임 정도를 재annotation해서 경계 위치 편차를
재면 측정량이 된다.** §7이 증명한 대로 라벨 자체에서는 추정할 수 없으므로 이것이 유일한
경로이고, "라벨 불확실성을 **측정해서** loss에 넣었다"는 훨씬 강한 주장이 된다.
비용은 사용자 시간뿐이다.

## 13. `L_range` -- 방위각 자유거리 보조항 (2026-08-23)

**상태: 구현·테스트·캘리브레이션 완료. 스윕 미실행.**

`L = ½L_F + ½L_N + λ_B·L_boundary + λ_R·L_range`. 구조는 그대로이고 항이 하나 붙는다 --
**soft-BCE를 대체하지 않는다.** 광선당 스칼라 하나라 한쪽에서 free를 넘치게 찍고 다른 쪽에서
부족하게 찍어 상쇄시키면 값이 맞아 버리므로, 2D 위치를 잡는 일은 계속 `L_boundary`가 한다.

### 13.1 왜 이 항인가 (사용자 설계)

현행 loss는 **셀마다 독립인 BCE의 합**이라 광선 방향으로 셀을 묶는 항이 하나도 없다. 그래서
"이 방향으로 free가 몇 m까지 이어진다고 예측했는가"를 어떤 항도 직접 묻지 않는다. 결과로
per-cell BCE가 거의 벌하지 않는 오차 모드가 남는다 -- **벽 뒤의 free 섬** 하나는 셀 몇 개분
BCE만 물지만 그 방향의 자유거리는 통째로 망가진다.

**dead zone이 이 설계의 핵심이다.** `e^eff = max(0, e − δ_R)`로 두면 δ_R 안에서 loss가
평평해져 gradient가 정확히 0이 되고, **모델이 그 자유도에 용량을 쓸 수 없다.** 단순 MAE로
걸면 §9.5의 원인 (3)(soft target도 경계 **위치**는 라벨에 못박는다)을 보조항이 다시 강요해
병을 키운다.

**이것은 §12.2의 허용오차 F1과 같은 메커니즘이고 좌표계만 다르다.** 허용오차 F1은 2D 셀
공간에서 어느 방향의 변위든 용서하고, 이 항은 광선당 스칼라에서 **반경 방향** 변위만 용서한다.
그리고 §5.2의 유도(`R_true = R_gt + ε`)가 애초에 **반경 변위**이므로 불확실성 가정이 원래
살던 좌표계로 돌아온 형태다. §2.1이 `d`를 수직 거리로 고른 것과 모순되지 않는다 -- 그건
"어느 셀을 부드럽게 하나"의 결정이었고 이건 "허용 폭을 어느 좌표에서 재나"의 결정이다.

### 13.2 목표는 `R_gt`가 아니라 `arc`다 -- 실측 0.758 m 편차

```
arc_gt  = Δr · Σ_k [free_gt]_k          (광선 위 GT free 셀 길이)
arc_hat = Δr · Σ_k p_k                  (같은 연산자, 확률로)
e_θ = |arc_hat − arc_gt|,   e^eff = max(0, e_θ − δ_R),   L_range = mean_θ∈OK ρ_β(e^eff)
```

**`polar.first_free_range`의 `R_gt`를 목표로 쓰면 안 된다.** `R_gt`는 ego 원점부터의
반지름이고 그 함수의 계약은 ego 아래 `permanent_blind` 원반을 **건너뛰고 잰다**는 것이다.

| val split 40프레임 실측 (`raws1`, `rawos3`) | 평균 |
|---|---|
| `R_gt` (첫 hit 반지름) | 1.668 m |
| `Δr·Σ(free_gt)` (arc) | 0.910 m |
| 첫 free 셀 반지름 | 0.793 m |
| **`R_gt − arc`** | **0.758 m** (프레임간 σ 0.059) |

**`δ_R = 0.20`의 3.8배인 계통 편차다.** 그대로 쓰면 dead zone이 무력화되고, loss가 그 상수를
줄이려고 **원반 안을 free로 예측하라고 요구한다** -- 원반은 hard `Ω_N`(목표 0)으로 감독되는
자리라 두 항이 정면으로 싸운다. 예측과 목표에 같은 연산자를 쓰면 편차가 정의상 사라지고,
부수 효과로 720광선·0.5셀 표본화와 라벨 raycast의 이산화 불일치(실측 0.035 m)도 상쇄된다.
`arc`와 `R_gt`는 거의 정적인 per-θ 상수만큼만 다르므로 **`δ_R`의 물리적 뜻은 보존된다.**

합은 광선 **전체**에 걸린다(첫 장애물 앞까지가 아니다). GT free는 ego 원점 raycast의 결과라
광선 위에서 연속 구간 하나이므로 GT에서는 두 정의가 같지만, **예측에서는 다르고 그 차이가
이 항이 잡으려는 오차 모드다** -- 벽 뒤 free 섬이 `arc`를 늘려 벌을 받는다.

**`RAY_OK` 광선만 쓴다** (실측 train 42.5 % / val 37.2 %). `RAY_NO_FREE`(53 %)는 목표가 0이고
이미 hard `Ω_N`으로 학습되므로 넣으면 광선 평균의 절반이 상수 0인 항이 되어 `λ_R`의 실효
크기가 2배 희석된다. `RAY_CENSORED`(12 %)는 **하한만 아는** 광선이라 양방향 loss를 걸면 모르는
값을 목표로 삼는 것이 된다. M3(`free_space_metrics.range_error`)가 정한 규약과 같은 판단이다.

`δ_R`과 `β`는 **미터로 둔다.** `R_max`로 정규화하면 실효 오차가 항상 β보다 훨씬 작아져
**Huber가 순수 L2로 퇴화**하고 outlier 강건성이라는 도입 이유가 사라진다.

### 13.3 `λ_R`은 추측하지 않고 gradient 비로 캘리브레이션한다

`L_range`는 미터, BCE는 nats라 두 항의 절대값에 공통 스케일이 없다. 그래서 `λ_R`을 숫자로
고르면 **그 숫자의 뜻이 정해지지 않는다.** 재는 것은 하나다.

```
G_R/G_B = ‖∂(λ_R·L_range)/∂logits‖ / ‖∂L_soft-boundary/∂logits‖
```

`logits`에서 재는 이유: 두 항이 만나는 유일한 공통 지점이고 그 아래로는 chain rule이 같은
인자를 곱해 비율이 보존된다. 도구는 `tools/measure_range_gradient.py`.

**실측 (δ=0.15 α=0.5 λ_B=0.5, `λ_R = 1`에서, `rep_..._s0` 체크포인트).**

| 시점 | train `arc_mae` | `G_R/G_B` (δ_R=0.20) | `G_R/G_B` (δ_R=0) |
|---|---|---|---|
| init (from scratch) | 0.833 m | **1.550** | - |
| ep10 | 0.144 m | **0.424** | - |
| ep20 | 0.090 m | **0.273** | - |
| ep40 | 0.043 m | **0.147** | **0.542** |
| ep40 (**val 프레임**) | **0.257 m** | **0.183** | **0.271** |

읽어야 할 것이 셋이다.

1. **`arc_mae`의 train/val 격차가 6배다** (0.043 대 0.257). 즉 이 양도 §9.5가 특정한 암기
   구조를 그대로 갖고 있다 -- **보조항이 실제로 일반화 실패가 있는 자리를 보고 있다는 뜻이다.**
2. **dead zone이 train gradient의 73 %를 없애는데 val gradient는 32 %만 없앤다**
   (train 0.542→0.147, val 0.271→0.183). 이것이 이 설계가 노린 것의 직접 측정이다 --
   **dead zone은 암기 규모의 오차(대부분 δ_R 안)를 우선적으로 지우고 큰 오차의 gradient는
   남긴다.** (단 이것은 `L_range` 없이 학습된 모델에 대한 정적 탐침이고 학습 결과가 아니다.)
3. **비율이 학습 진행에 따라 10배 떨어진다**(1.55 → 0.147). 즉 **한 `λ_R` 값으로 전 구간에서
   목표비 0.1을 유지할 수 없다.** 그래서 스윕에서 0.1과 0.3으로 괄호를 친다 -- 0.3이
   ep10~20에서 0.1 근처(0.13/0.08)이고, 0.1은 전 구간에서 확실히 보조 규모다.

부수 관찰: **`arc_bias`가 val에서 +0.088 m**로 이미 자유공간 과대예측 쪽이다. dead zone이
`|e|`에 대칭이므로 그 방향(= `fatal`)이 무벌점으로 늘어날 수 있다. §4.5의 제약이 여기 걸리고,
`fatal_rate`를 판정 제약으로 계속 읽어야 한다. **비대칭 dead zone은 §13.8에서 실측했다.**

### 13.4 스윕 계획 -- `λ_B`를 내리는 칸이 핵심이다

`configs/sweep_range_loss.sh`. 베이스는 프론티어 중간점(gaussian, δ=0.15, α=0.5).

| 런 | λ_B | λ_R | δ_R | 무엇을 묻나 |
|---|---|---|---|---|
| `sb_r30_dr00` | 0.5 | 0.3 | **0.0** | dead zone이 필요한가 |
| `sb_r10` | 0.5 | 0.1 | 0.20 | **A** -- 약한 순수 보조항 |
| `sb_r30` | 0.5 | 0.3 | 0.20 | **A** -- 캘리브레이션된 보조항 |
| `sb_r30_lb25` | **0.25** | 0.3 | 0.20 | **B** -- 몫을 옮기면 프론티어가 옮겨지나 |
| `sb_r30_lb12` | **0.125** | 0.3 | 0.20 | **B** -- 극단 |

**A와 B를 나눠야 하는 이유.** `λ_B = 0.5`를 그대로 두고 보조항을 얹는 것(A)은 지표 개선은
할 수 있지만 **원인 (3)을 완화할 수 없다** -- train/val KL 격차를 만드는 것이 `λ_B` 항 자신인데,
셀당 계수 5.17/\|V\|의 관용 없는 항이 `G_R/G_B ≈ 0.1`의 관용 있는 항보다 10배 세게 남기
때문이다. 프론티어를 옮기려면 **경계 감독의 몫을 관용 있는 형태로 이전**해야 하고 그것이 B다.
§10.4가 `λ_B` 0.5 → 0.25를 단독으로 시험해 **지배됨**(f1 −0.0046, val kl 악화)을 실측했는데,
그때는 빼낸 감독을 대신 공급할 것이 없었다. 그래서 `sb_r30_lb25`의 대조군이 공짜로 있다.

**판정 기준.** `f1@10cm` 한 점이 아니다(§12.2의 검증 예측).

1. **train/val KL 격차**(현재 28~42배)가 줄고 val KL 곡선이 내려가서 **머무는지** -- 프론티어
   이동의 직접 증거
2. `f1@10cm` + 되올림의 (성능, 수렴) 쌍이 §11.2의 교환 곡선 **밖으로** 나가는지
3. `fatal_rate`가 나빠지지 않는지 (`arc_bias`와 함께 읽는다)
4. `iou_free`가 σ√2 = 0.0021보다 크게 떨어지지 않는지 (§4.5)

**`range_mae`를 판정에 쓰면 안 된다.** 이 항을 넣는 순간 그 지표는 학습 목표의 근친이 되어
독립 판독값이 아니다 -- §5.7이 "우리의 가정으로 우리를 채점하면 안 된다"고 박아둔 원칙이
그대로 걸린다. (엄밀히는 `arc`와 M3의 argmax 첫 hit가 다른 양이지만 판정 근거로는 너무 가깝다.)

**전부 torch로, 배치의 라벨에서 매번 다시 계산한다.** `arc_gt`를 `__getitem__`에서 미리 계산해
배치에 실을 수도 있었지만 그러면 좌우 반전 증강에서 조용히 틀린다 -- `(n_theta,)` 배열의 좌우
반전은 공간 축 flip이 아니라 `θ → 2π − θ`, 즉 **순열**(`roll(flip(x), 1)`)이고,
`_MIRRORED_KEYS`에 그냥 넣으면 `torch.flip`이 걸려 광선 대응이 어긋난다. 이미 반전된 라벨
텐서에서 뽑으면 **θ 축이 저장되지 않아 그 함정이 아예 생기지 않는다.** 비용은 고정 인덱스
gather 한 번(프레임당 720×200)이라 사실상 0이다.

`ray_is_ok`는 `polar.first_free_range`의 `RAY_OK` 판정을 torch로 다시 구현한 것이고,
`test_ray_is_ok_matches_first_free_range`가 두 구현이 **광선 하나까지 일치**하는 것을 고정한다.

**`λ_R = 0`이면 항이 계산조차 되지 않는다** -- 대조군과 기존 스윕 런이 새 코드 경로를 타지
않아야 하고, `--lambda_r > 0`은 `--loss=soft_boundary`에서만 허용된다.

같이 나빠졌다. `f1`·`iou`·`fatal`이 전부 악화된다. **보조항은 경계 감독을 대체하지 못한다.**
§10.4의 결론이 관용 있는 대체 신호를 공급해도 유지된다. §13.4가 "핵심"이라 적은 칸의 답은
**아니오**다.

**(2) A 조건은 소폭 성공이고 `sb_r30`이 유일한 좋은 점이다.** 전 스윕에서 **val kl이 실제로
내려간 런은 이것 하나뿐이다**(−2.8σ). 그러면서 KL 배율이 37.72 → 35.19(−10.6σ)로 줄고
`f1`·`iou`·`fatal`은 전부 노이즈 안에 머문다. 즉 **성능을 해치지 않고 수렴 축을 조금 밀었다.**

**(3) dead zone의 효과는 경계 KL에는 안 보이고 `arc` 자체에만 보인다.** δ_R=0이 arc 배율
**7.0×**인데 δ_R=0.20이면 **5.0×**로 줄어든다 -- dead zone이 설계대로 arc의 암기를 억제한다.
그런데 **경계 KL 배율은 δ_R=0이 오히려 약간 낫다**(34.73 대 35.19, 1.9σ로 사실상 동률).
**즉 KL 배율 개선을 만든 것은 dead zone이 아니라 광선 결합 항의 존재 자체다.** 다만 δ_R=0은
`iou_free`(−2.5σ)와 `free_miss`(+3.7σ)가 나빠지고 val kl 개선도 없어, **최종 선택은 여전히
δ_R=0.20이다.**

**(4) 대칭 dead zone이 `fatal` 방향을 허용한다 -- §13.3의 우려가 실측됐다.** `arc_bias`가
전 런에서 **+0.063 ~ +0.086 m**로 일관되게 양수(자유공간 과대예측)이고, `sb_r10`은 `f1`을
+2.2σ 올리는 대가로 **`fatal`을 +7.8σ 악화**시킨다. `f1`만 보면 `sb_r10`이 스윕 최고점이지만
**안전 지표를 팔아서 산 것**이므로 채택하지 않는다.

**(5) 프론티어는 의미 있게 옮겨지지 않았다.** 어느 런도 (성능, 수렴) 두 축 모두에서 2σ를
넘게 개선하지 못했다. §12.2가 미리 적어 둔 "안 되면 그것도 결과다"에 해당한다.

### 13.6.4 그래서 다음은 무엇인가

**판정 프로토콜을 먼저 고쳐야 한다.** 현행 규약(단일 런 ep40 `f1@10cm`)은 σ_run 0.0037이라
이 프로젝트가 재려는 크기(0.002~0.005)를 **원리적으로 해상할 수 없다.** 남은 실험을 이 규약으로
돌리면 §10처럼 노이즈를 결론으로 읽게 된다. 최소 세 가지를 바꾼다.

1. **모든 A/B는 런 3반복이 기본이다**(같은 시드로도 갈리므로 시드 반복과 별개다). 3반복이면
   평균의 표준오차가 0.0021로 내려가 0.005급 효과를 2σ로 잡을 수 있다. 런당 7~15분이라 비용은
   문제가 아니다 -- §9~§11이 n=1이었던 이유는 비용이 아니라 σ를 몰랐기 때문이다.
2. **주 판정을 저분산 축으로 옮긴다.** `되올림`(σ 0.53pp) · `KL 배율`(σ 0.24×) ·
   `iou_free`(σ 0.0007) · `fatal`(σ 0.0005)은 단일 런으로도 판정 가능하다.
   `f1@10cm`은 3반복 평균으로만 쓴다.
3. **§9~§11의 표에 σ_run을 병기하고, 위 13.6.2의 재판정을 반영한다.**

그 다음이 §12.2의 **허용오차 F1**이다. 아직 시도하지 않았고, 이제 **효과가 `f1` 0.0075
이상이어야 단일 런으로 검출된다**는 것을 알고 시작한다. 다만 13.6.3(3)이 보여준 것 --
dead zone이 `arc`의 암기는 억제했는데 경계 KL은 못 움직였다 -- 는 허용오차 F1에 대한
사전 정보다: **2D 셀 공간에서 관용을 주는 것도 경계 KL을 못 움직일 가능성이 있다.**
그 경우 §26.5의 "경계의 환원 불가능한 불확실성"이 강한 근거를 얻는다.

`L_range`의 최종 상태는 **`λ_R = 0.3`, `δ_R = 0.20`, `β = 0.10`을 유지하되 `λ_B = 0.5`를
건드리지 않는다**(= `sb_r30`). 성능 중립이고 수렴을 조금 개선하므로 남길 가치는 있지만,
**이것이 프론티어를 옮겼다고 주장하면 안 된다.**

> **[2026-08-23 정정 -- 아래 표의 σ를 인용하지 말 것. §15.4가 정본이다.]**
> 이 표의 σ는 σ_run(**같은 시드**의 재현 노이즈)으로 계산됐는데, `ce`의 **시드 간** 분산이
> 그보다 3~13배 크다(`fatal_rate`: σ_run 0.0005 대 시드 분산 0.0063). n=3 ablation의 정정값:
> `fatal_rate` **−9.2 %(2σ, 경계)**, `missed_obstacle` **−16.1 %(3σ)**,

## 13.8 비대칭 dead zone -- 과대예측 쪽만 좁힌다 (2026-08-23)

> **[2026-08-23 정정]** 이 절의 판정은 전부 n=1·σ_run 기준이다. §15.4가 그 문턱이 3~13배
> 과소평가였음을 실측했으므로 **아래 σ 값을 인용하지 말 것.** `ov00`의 `fatal` −3.9σ /
> `free_miss` +6.7σ는 시드 분산 기준으로 다시 재야 하고, 이번 n=3 ablation에는 이 칸이
> 없으므로 **미확인 상태로 남는다.** 확정 config는 여전히 대칭 δ_R = 0.20이다.

**실행:** `configs/sweep_range_asymmetric.sh`, 시드 0, 40 epoch, 대표 split.
베이스는 §13.6.1의 n=5 평균이고 `sb_r30`(대칭 δ_R=0.20)은 §13.6.3에 이미 있다.

### 13.8.1 왜 이 손잡이인가

§13.7이 두 가지를 같이 실측했다.

1. `arc_bias`가 전 런에서 **+0.063 ~ +0.086 m** -- 모델이 일관되게 자유공간을 과대예측한다
2. `λ_R = 0.1` 런(`sb_r10`)은 `f1` +2.2σ를 사려고 **`fatal`을 +7.8σ 팔았다**

그런데 §14가 주 판정 지표를 `fatal_rate`·`missed_obstacle`로 옮겼다. **즉 대칭 dead zone은
판정하기로 한 축을 δ_R까지 무료로 허용하고 있었다** -- "벽 안쪽 20 cm까지 free 예측"이 무벌점이다.

`arc_hat > arc_gt`(과대예측)는 **없는 자유공간을 있다고 예측한 것**이고 로봇에게 치명 방향이다.
반대쪽(보수)은 라벨 불확실성과 구별되지 않고 비용도 낮으므로 `δ_R⁻ = 0.20`으로 넓게 유지한다
(§4.5). 구현은 `range_loss.compute_range_loss(delta_r_over=)`이고 두 hinge의 합이다:

```
e^eff = relu(signed − δ_R⁺) + relu(−signed − δ_R⁻),      signed = arc_hat − arc_gt
```

### 13.8.3 읽은 것

**(1) `δ_R⁺ = 0.10`은 아무것도 하지 않는다.** 전 지표가 `sb_r30`과 구별되지 않고 `arc_bias`도
+0.078 → +0.076으로 그대로다. **전이는 0과 0.10 사이에 있다.**

**(2) `δ_R⁺ = 0`은 겨냥한 축을 실제로 움직였다.** 전 스윕에서 **`fatal_rate`가 개선된 유일한
런**이다(0.1262 → 0.1243, −3.9σ). `arc_bias`가 +0.078 → +0.058로 실제로 줄고 `range_bias`도
같은 방향(−1.9σ)이다 -- **loss가 과대예측을 벌하기 시작하니 모델이 덜 과대예측한다.** 인과가
깔끔하다.

**(3) 안정성 두 축에서 스윕 최고다.** 되올림 14.94 %(−4.5σ), KL 배율 34.73×(−12.6σ). 정확도를
무너뜨리지 않은 런 중 최저이고, `iou_free`·`f1`·`range_mae`·`missed_obstacle`은 노이즈 안이다.

**(4) 대가는 보수성이다.** `free_miss_rate` 0.0969 → 0.1000(+6.7σ). 절대값으로 **`fatal` 1셀을
줄이려고 `miss` 1.6셀을 지불한다.** 충돌 비용이 우회 비용보다 훨씬 크다는 전제라면 좋은
교환이지만 **이것은 로봇 운용 판단이므로 사용자가 정한다.**

**(5) tension이 하나 있다.** `δ_R⁺ = 0`은 그 방향의 관용을 완전히 없앤 것이므로 dead zone의
원래 논거(라벨 오차를 외우지 않는다)를 포기한 것이다. 실제로 **arc 배율이 5.0× → 6.8×로
나빠졌다** -- **경계 항의 암기(KL 배율)는 줄었는데 거리 항의 암기는 늘었다.** `share_r`도
0.0033 → 0.0152로 4.6배 커졌다(항이 더 많은 일을 한다).

**(6) `missed_obstacle`은 안 움직였다**(−0.2σ). 즉 `ov00`은 치명 오차의 **면적**은 줄였지만
광선 단위로 **장애물을 통째로 놓치는 것**은 줄이지 못했다. 두 실패의 기제가 다르다는 뜻이다.

### 13.8.4 미결 -- 확정하지 않았다

**`ov00` 채택 여부는 보류 상태다**(사용자 결정 대기). 결정의 핵심은 `fatal` 1셀당 `miss`
1.6셀이 받아들일 만한가이고 그것은 로봇 운용 판단이다.

**권고하는 추가 런 하나: `δ_R⁺ = 0.05`(1셀).** 0.10이 무효이고 0이 작동했으므로 전이가 그

`miss` 비용 없이 가져올 수 있는지**를 묻는다(런당 약 8분).

현재 확정 config는 여전히 **`sb_r30`**(대칭 δ_R = 0.20)이다.

### 15.3 되올림은 loss 종류를 넘어 비교할 수 없었다 -- 엔트로피 하한 보정

**사용자 지적:** "loss function 자체가 변하는데 절대 수치만으로 비교하면 안 되는 게 맞을
테고, 그러면 '더 안정적으로 수렴한다'는 걸 어떻게 주장하나."

맞는 지적이고 결함이 실재했다. val loss를 `c + r(t)`로 쓰면 (`c`는 모델과 무관한 상수)

```
되올림 = (c + r_last)/(c + r_min) − 1 = (r_last − r_min)/(c + r_min)
```

이므로 **`c`가 클수록 비가 기계적으로 작아진다.** soft-boundary loss의 경계 항에는 target
엔트로피가 `λ_B·H̄ = 0.5 × 0.299 = 0.1496`으로 들어 있다(§5.4). 양쪽에서 빼면

| | 생 되올림 | **하한 제거** |
|---|---|---|
| `A_ce` | 61.8 % | 61.8 % (하한 없음) |
| `C_soft` | 17.8 % | **25.6 %** |
| `D_range` | 13.8 % | **19.3 %** |

**생 되올림은 soft loss에 유리하게 약 45 % 부풀려져 있었다.** 결론(되올림이 크게 줄었다)은
유지되지만 크기는 3.5배가 아니라 **2.4배**다. `report_ablation.py`가 두 값을 다 낸다.

되올림에는 남은 결함이 두 개 더 있고 이건 보정할 수 없다 -- **최저점 epoch이 셀마다
다르고**(A 5.7 / B 16.0 / C 3.7 / D 5.0) **종점 40이 임의다.** 그래서 창의 길이 자체가 다르다.

**그리고 결정적으로, 되올림을 고쳐도 품질이 안 변한다는 선례가 이미 있다** -- 진단 문서
§17.1의 `label_smoothing 0.05`가 val loss 증가배수를 1.59 → 1.09로 만들어 발산을 완전히
멈췄는데 지표는 전부 노이즈 안이었다. **되올림은 증상이다.**

**결론: 되올림은 보조 근거로 내린다.** 주 근거는 loss가 등장하지 않는 축이어야 한다 --
`iou_free`·`fatal_rate`는 정의가 loss 종류와 무관하므로 아래 세 개가 안전하다.

| 안전한 안정성 지표 | 무엇을 묻나 |
|---|---|
| `iou 최고→끝 하락` | 어디서 멈춰도 같은 모델을 얻나 |
| `val fatal/iou 흔들림`(마지막 10 ep σ) | 곡선이 진동하나 |
| `train−val iou 격차` | 외우나 |

### 15.4 [철회] σ_run으로 CE와 soft를 비교한 모든 판정은 σ가 부풀려져 있었다

**이 세션의 가장 중요한 발견이고, §13.6.1이 만든 문턱 자체의 한계다.**

σ_run은 **config가 같고 시드까지 같은** 런들의 산포다(§13.6.1). 그런데 CE의 **시드 간**
산포는 그보다 훨씬 크고, 게다가 **soft 런보다 크다.**

| 시드 간 표준편차 | `A_ce` | `C_soft` | `D_range` | A/D 배 | F(2,2) |
|---|---|---|---|---|---|
| `fatal_rate` | 0.0063 | 0.0017 | **0.0007** | **9.3×** | 유의 |
| `range_bias` | 0.0190 | 0.0058 | **0.0023** | **8.4×** | 유의 |
| `missed_obstacle` | 0.0047 | 0.0011 | **0.0010** | 4.8× | 유의 |
| `free_miss_rate` | 0.0055 | 0.0023 | **0.0011** | 4.8× | 유의 |
| 되올림(생) | 13.6pp | 3.9pp | **3.0pp** | 4.6× | 유의 |
| `range_mae` | 0.0069 | 0.0013 | 0.0024 | 2.9× | – |
| `iou_free` | 0.0010 | 0.0014 | 0.0010 | 1.0× | – |
| `f1@10cm` | 0.0093 | 0.0092 | 0.0067 | 1.4× | – |
| `f1@20cm` | 0.0084 | 0.0098 | 0.0088 | 1.0× | – |
| 선택 ep | 7.4 | 7.6 | 8.1 | 0.9× | – |

`fatal_rate`에서 σ_run은 0.0005(ep40) ~ 0.00225(선택 epoch, n=4)인데 CE의 시드 분산은
**0.0063**이다. 즉 문턱을 **3~13배 과소평가**했다.

**그래서 §13.7.2의 σ를 아래로 정정한다.** 방향과 크기는 살아남고 σ만 줄어든다.

| | §13.7.2 (n=1, σ_run) | **§15 (n=3, 시드 분산)** |
|---|---|---|
| `fatal_rate` | −5.2 % (14σ) | **−9.2 % (2σ, 경계)** |
| `missed_obstacle` | −11.5 % (8.4σ) | **−16.1 % (3σ)** |
| `free_miss_rate` | +8.9 % (17σ, 악화) | **+16.4 % (5σ, 악화)** |
| 되올림 | −74 % (94σ) | **−68.7 % (7σ, 하한 제거)** |
| `iou_free`·`f1@{10,20}` | 노이즈 | **노이즈** (유지) |

**§13.6.3·§13.8의 σ도 같은 방향으로 부풀려져 있다**(둘 다 σ_run 기준 n=1 판정이다). 그 절의
*순위*는 인용해도 되지만 *σ 값*은 인용하면 안 된다.

> **교훈:** σ_run은 "같은 실험을 다시 돌렸을 때의 재현 한계"이고 **하한**이다. **서로 다른
> config를 비교할 때는 시드 분산을 써야 하고, 그건 config마다 다르다.** CE는 soft보다 4~9배
> 더 흔들린다 -- 그 자체가 아래 §15.5의 주 결과다.

### 15.5 확정되는 결과 세 가지

> **[2026-08-23 철회 -- 아래 (3)은 취소됐다. §16이 정본이다.]**
> (3)의 "안전 지표 개선"은 **동작점(threshold) 이동이었다.** τ를 쓸어 같은 `free_miss`에서
> 비교하면 CE와 `D_range`의 `fatal`·`missed_obstacle` 곡선이 **시드 σ 안에서 겹친다.**
> CE도 τ를 0.5 → 0.7로 올리면 같은 자리에 온다. **(1)과 (2)는 유효하다** -- (1)은 모든 τ에서
> 성립하고(§16.2), (2)는 학습 동역학이라 τ와 무관하다.

**(1) 가장 크고 일관된 것 -- 런마다 같은 결과가 나온다.** §15.4의 표가 그 자체로 결과다.
좁아진 것은 `fatal`·`missed`·`free_miss`·`range_bias`, 즉 **"경계를 어디에 놓나"** 계열이고,
`iou_free`·`f1@{10,20}cm`(전체 분할 품질)은 **변화가 없다**(1.0~1.4배). soft-BCE가 경계
불확실성을 다룬다는 설계 의도와 정확히 일치한다.

실무적 의미: CE로 학습하면 같은 설정을 다시 돌려도 `fatal_rate`가 ±0.0063 흔들려 **실험을
비교할 수 없다.** `D_range`는 ±0.0007이다.

**(2) 되올림이 2.4배 줄어든다.** 61.8±13.6 % → 19.3±4.3 %(하한 제거, 7σ).

**(3) 안전 지표가 좋아지고 자유공간 탐색이 나빠진다.** `missed_obstacle` −16.1 %(3σ),
`fatal_rate` −9.2 %(2σ 경계), 대가로 `free_miss_rate` +16.4 %(5σ). **덜 공격적으로 예측한다.**

**정확도는 CE와 동일하다** -- `iou_free` +0.0000, `f1@10cm` −0.0055, `f1@20cm` −0.0015,
`range_mae` −0.0024, 전부 노이즈 안. 라벨이 부정확하니 정확도 개선에 상한이 있다는 §14의
전제가 이 실험으로 확인됐다.

### 15.6 각 항이 실제로 한 일

**`B_perset`(per-set 평균만)은 함정이다.** 안정성 지표를 다 이긴다 -- `train−val iou 격차`
0.0712(12σ 개선, 전 셀 최고), 되올림 4.7 %(최고), val 최저 ep 16.0(최고). 그런데 **품질은
전부 최악**이고(`f1@10cm` −12σ, `iou` −8σ, `fatal` +4σ, `missed` +7σ), 게다가
**`iou 최고→끝 하락`이 오히려 최악이다**(0.0122 vs A 0.0009).

`λ_B = 0`이면 경계 대역 셀 11.6 %가 감독에서 아예 빠진다. **안 배우니 안 외운다 --
underfitting이고 안정성 개선이 아니다.**

> **방법론 교훈: 안정성 지표는 단독으로 읽으면 "아무것도 안 배우는 것"이 항상 1등이다.**
> 반드시 품질과 같이 읽어야 한다. 그리고 loss 곡선이 얌전한 것과 지표가 안 무너지는 것은
> **다른 일이다** -- `B_perset`이 그 둘을 정반대로 보여준다.

**soft 경계 항(B→C)이 실제 일꾼이다.** 품질 8개 전부 회복한다 -- `f1@10cm` +12σ,
`iou` +9σ, `fatal` −6σ, `missed` −10σ, `range_mae` −7σ, `range_bias` −6σ. 대가로 안정성이
되돌아가지만(격차 +13σ, 되올림 +3σ) CE 대비로는 되올림이 여전히 6σ 좋다.

**`L_range`(C→D)는 평균을 옮기지 않고 산포를 줄인다.** 계단별로 유의하게 남은 것은
**`train/val KL 배율` 37.03 → 34.87 (3σ)** 하나뿐이다 -- 품질 8개, iou 하락, 흔들림, 격차,
되올림 전부 노이즈. 그러나 시드 산포가 좁아진다(`fatal` σ 0.0017 → 0.0007, `range_bias`
σ 0.0058 → 0.0023).

> **§13.6.3의 "λ_R = 0.1은 f1 +2.2σ를 사려고 fatal을 +7.8σ 팔았다"와 §13.8의 판정은 전부
> n=1·σ_run 기준이므로 σ를 다시 읽어야 한다.** 이번 n=3에서 `sb_r10`에 해당하는 칸은 돌리지
> 않았으므로 그 비교는 **미확인 상태로 남는다.**

### 15.7 시드 0만 봤을 때 틀렸던 판정 (기록용)

n=1과 n=3이 갈린 지점이다. **`A_ce`의 시드 분산이 커서 시드 0이 CE에게 유난히 나쁜
런이었다**(`fatal` 0.1430 vs 평균 0.1364).

| A→D | 시드 0 판정 | n=3 판정 |
|---|---|---|
| `f1@10cm` | +16σ 좋아짐 | **노이즈** |
| `iou_free` | +2σ 좋아짐 | **노이즈** |
| `fatal_rate` | 3σ 좋아짐 | 2σ (경계) |

그리고 C→D의 `f1@10cm` −16σ도 사라졌다(−0.0084, 1σ). 그것은 **선택 epoch 차이**(C 19 대
D 36)가 섞인 것이었다 -- 같은 epoch에서 다시 재면 ep19에서 −0.017, ep36에서 −0.006이고,

### 15.8 과적합에 대해 -- 파라미터로 고칠 수 없다는 것은 이미 실측돼 있다

**사용자 질문:** "val loss 수렴이 너무 빨리 되는 것 같다. 과적합이 너무 빨리 일어난다.
파라미터 세팅의 영역인가?"

**(a) 두 곡선이 다른 것을 재고 있다.** val loss는 ep 3.7~5.7에서 최저인데 `iou_free`는
ep 26~31에서 최고다. val loss의 84 %가 경계 대역에서 나오고(§7.2의 `share_boundary` 0.844)
그게 라벨이 못 믿는 자리다. **`iou` 기준으로는 최고점→ep40 하락이 A 0.0009 / C 0.0015 /
D 0.0007로 거의 없다.** 즉 "과적합이 빨리 온다"는 val loss의 성질이지 모델의 성질이 아니다.

**(b) 파라미터 손잡이는 전부 기각돼 있다** (진단 문서 §10.2, §17.1, §19):

| 손잡이 | 실측 | 판정 |
|---|---|---|
| `weight_decay=0.5` (가중치 −7 %) | train iou **0.9901**, val +0.0039 | Adam이 축소를 즉시 되돌린다 |
| `res50` (encoder 37→18 M) | train iou **0.9756 -- 오히려 높다** | **"커서 외운다"가 기각** |
| `freeze_encoder` | val 0.7120 (−0.088) | encoder는 반드시 적응해야 한다 |
| `flip_augment` | `IoU(free, mirror(free))` 0.4947, 리그 자기 거울상 0.8562 | 장면이 좌우 비대칭 |
| `label_smoothing=0.05` | 증가배수 1.59 → 1.09, 지표 그대로 | 증상만 없앤다 |

**(c) 결정적 반증:** train을 20 % 버렸더니 val/train loss 비가 8.07 → 17.12로 두 배
나빠졌는데 `iou_free`는 0.8003 → 0.7969(노이즈 안)였다(진단 문서 §20.2). **과적합의 정도와
val 성능이 연결되어 있지 않다.**

**(d) 지목된 다음 병목은 입력 신호다** -- 진단 문서 §18.3, **미해결**.
`unproject_image_to_mem`이 `normalize_grid2d`(픽셀 인덱스 규약)로 정규화한 뒤
`grid_sample(align_corners=False)`(픽셀 가장자리 규약)로 표본한다. 특징맵 마지막 열이
63 → 31.50으로 죽고, 총 오프셋이 0.5~1 특징픽셀(10~20 native px)이다.

**(e) 라벨 부정확성 쪽으로 남은 것은 §12.2의 허용오차 F1 하나다.** soft-BCE가 경계 셀의
*확신*을 풀었고 `L_range`가 *반경 방향 위치*를 풀었으니, 2D 셀 공간에서 **어느 방향으로
밀려도** 용서하는 항이 마지막 조각이다.

## 16. Threshold sweep -- "안전 개선"은 동작점 이동이었다 (2026-08-23, 외부 검토 제안)

**여기가 이 loss 연구의 최종 결론이다.** §15.5(3)을 철회하고, 살아남은 주장이 하나임을
확정한다.

### 16.1 무엇을 물었고 왜 물어야 했나

외부 검토자(GPT)의 제안이다. 우리가 §15.5(3)에서 "안전 개선"이라고 부른 것은

```
fatal      0.1364 -> 0.1239   (-1.25 pp)
missed_obs 0.0439 -> 0.0369   (-0.70 pp)
free_miss  0.0847 -> 0.0986   (+1.39 pp)
```

인데, **이 패턴은 representation이 좋아져도 나오고 결정 threshold가 올라가도 나온다.**
`fatal`↓ / `free_miss`↑는 τ를 올리면 자동으로 생기는 교환이다. 둘을 가르는 방법은 하나뿐이다:
**τ를 쓸어 `(free_miss, fatal)` 곡선을 그리고, 같은 `free_miss`에서 비교한다.**

- 곡선이 겹치면 → **동작점 이동.** CE도 τ만 바꾸면 공짜로 같은 것을 얻는다
- 같은 `free_miss`에서 항상 soft가 `fatal`이 낮으면 → **진짜 교환 곡선 개선**

**우리는 이 대조를 한 번도 하지 않았다.** 모든 판정을 τ=0.5(=`argmax`) 한 점에서만 읽어 왔다.

### 16.2 실측 -- 곡선이 겹친다

val 75프레임, 시드 3개, τ ∈ {0.20 ... 0.80} 9점. 지표 정의·평가 경로는 학습 루프와 **동일**
(`free_metrics_from_masks` / `range_error` / `tolerance_counts`, `pred_free = p > τ`).

**같은 `free_miss`에서의 `fatal`** (곡선 선형보간):

| `free_miss` | `A_ce` | `C_soft` | `D_range` | A−D |
|---|---|---|---|---|
| 0.0850 | **0.1361** | 0.1387 | 0.1404 | −0.0043 |
| 0.0900 | **0.1306** | 0.1324 | 0.1339 | −0.0033 |
| 0.0950 | **0.1256** | 0.1268 | 0.1280 | −0.0024 |
| 0.0990 | **0.1219** | 0.1226 | 0.1235 | −0.0016 |
| 0.1040 | **0.1174** | 0.1178 | 0.1184 | −0.0010 |

`free_miss > 0.1049`는 `A_ce`의 곡선이 덮지 않는다(τ=0.80이 끝점). **끝값 고정을 보간으로
오독하지 않도록 도구가 `nan`을 찍는다** -- 처음 이 표를 쓸 때 0.1050을 앵커로 잡아 그 함정에
걸렸다.

**같은 `free_miss`에서의 `missed_obstacle`**: A−D가 +0.0006 ~ +0.0011로 **반대 방향이지만
같은 크기**다(0.0850에서 0.0438 대 0.0427, 0.0990에서 0.0373 대 0.0367).

**도구: `tools/report_threshold_sweep.py`** (출력 `runs/ablation/report_threshold.txt`).
forward는 모델당 한 번만 하고 τ는 캐시된 확률에서 쓴다. 지표는 학습 루프와 **같은 함수**를
쓰므로 **τ=0.5 행이 §15.2의 표와 일치해야 한다** -- 안 맞으면 평가 경로가 갈린 것이다.

두 차이가 전부 `A_ce`의 시드 σ(`fatal` 0.0033~0.0055) 안이므로 정직한 판정은 **"겹친다"**다
("CE가 낫다"도 주장하지 않는다).

**τ를 val에서 최적화했을 때** (낙관 편향이 있지만 세 칸에 동일하게 걸린다):

| 칸 | 최대 `iou_free` | @τ | 최대 `f1@10cm` | @τ |
|---|---|---|---|---|
| `A_ce` | 0.7992 | 0.70 | **0.5569** | 0.80 |
| `C_soft` | **0.7993** | 0.55 | 0.5566 | 0.55 |
| `D_range` | 0.7979 | 0.55 | 0.5490 | 0.60 |

**`D_range`의 τ=0.5는 `A_ce`의 τ≈0.7 자리다.** soft target이 대역에서 `p`를 내리므로 출력이
계통적으로 덜 free-확신적이고, 그것이 §15.5(3)의 전부였다.

> **결론: `L_soft-BCE`(+`L_range`)는 safety-conservativeness 교환 곡선을 바꾸지 않는다.**
> §15.5(3)을 철회한다.

### 16.3 살아남은 것 -- 재현성은 모든 threshold에서 성립하고 오히려 강해진다

`fatal_rate`의 **시드 간 σ**를 τ별로:

| τ | 0.20 | 0.30 | 0.40 | 0.50 | 0.60 | 0.70 | 0.80 |
|---|---|---|---|---|---|---|---|
| `A_ce` | 0.0080 | 0.0066 | 0.0058 | 0.0051 | 0.0045 | 0.0039 | 0.0033 |
| `C_soft` | 0.0019 | 0.0010 | 0.0010 | 0.0014 | 0.0019 | 0.0023 | 0.0024 |
| `D_range` | 0.0006 | 0.0003 | 0.0003 | 0.0006 | 0.0008 | 0.0008 | 0.0013 |
| A/D 배율 | 13× | 22× | 19× | **8.5×** | 5.6× | 4.9× | 2.5× |

**"평평한 구간에 있어서 σ가 작은 것"이라는 반론이 막힌다.** 오히려 `D_range`가 τ에 **더**
민감하다 -- `d(fatal)/dτ`가 −0.119 대 `A_ce` −0.061이다. 시드 분산을 **유효 threshold
jitter**로 환산하면

```
sigma_tau_eff = sigma_fatal / |d fatal / d tau|      ("시드를 바꾸는 것이 tau를 얼마나 흔드나")
    A_ce     0.0051 / 0.061 = 0.084
    C_soft   0.0014 / 0.127 = 0.011
    D_range  0.0006 / 0.119 = 0.005      -> A_ce의 17분의 1
```

즉 **두 시드가 "경계를 어디에 둘지"에 대해 훨씬 더 정확히 합의한다.** §15.5(1)의 강화다.

### 16.4 그래서 이 loss는 무엇을 주는가 (최종)

| 축 | 판정 |
|---|---|
| 정확도 (`iou_free`·`f1@τ`·`range_mae`) | **바뀌지 않는다.** τ를 최적화해도 CE와 구별 안 됨 |
| safety-conservativeness 교환 곡선 | **바뀌지 않는다** (§16.2) |
| **재학습 재현성** | **5~22배 좋아진다.** 모든 τ에서, 유효 threshold jitter 17배 (§16.3) |
| val loss 발산 | **±15 cm 경계 대역으로 국소화되고 크기가 절반 이하** (§8.1, CE +0.2003 대 D +0.0839) |
| 되올림 | 2.4배 감소 (학습 동역학이라 τ 무관) |

**한 문장: 더 좋은 모델을 주지 않고, 같은 모델을 더 일관되게 준다.**

실무적 이득의 정확한 크기: CE가 같은 동작점에 가려면 **τ를 val에서 골라야** 하고 그건
데이터가 바뀌면 다시 골라야 한다. soft-BCE는 τ=0.5에서 이미 그 자리에 있고 그 자리가 시드
간에 8배 덜 흔들린다. **그게 전부이고, 정확도 이득은 없다.**

### 16.5 표기 규약 (외부 검토 수용)

**절대값(pp)을 먼저 쓰고 상대값을 괄호에 둔다.** `fatal −9.2 %`가 아니라
`fatal −1.25 pp (−9.2 % relative)`다. 0.1364 → 0.1239는 percentage point로 1.25이고,
상대 9.2 %를 headline으로 쓰면 규모를 오해하게 한다. §15의 상대값 표기도 이 규약으로 읽는다.

### 16.6 "98.9 %가 편향"은 과한 표현이었다 (자체 정정)

`docs/temp/status_for_gpt_2026-08-23.md` §7.1에서 시드 3개 앙상블이 `iou_free` 격차의 1.1 %만
닫는다는 실측을 근거로 "남은 오차의 98.9 %는 라벨·task의 편향"이라고 썼다. **실측은 맞지만
해석이 과했고, 같은 문서 안에서 모순이었다** -- §9(4)에서 geometry 결함(§18.3)을 shared error
후보로 지목했는데 geometry는 라벨도 task도 아니다.

정확한 표현은 **"현재 modeling pipeline(같은 데이터·split·아키텍처·기하·라벨)이 공유하는
오차"**다. 세 시드는 초기화와 배치 순서만 다르므로, 앙상블은

```
label systematic error | train/val domain gap | architecture limit
camera information limit | geometry implementation error | single-frame task limit
```

중 무엇인지 **구분하지 못한다.** `irreducible bias`나 `task ceiling`이라고 부르지 않는다.

값싼 강화 방법(아직 안 함): `A_ce`·`C_soft`·`D_range` 9개를 **loss family 교차 앙상블**.
0.800 근처에서 멈추면 "loss 계열과 초기화를 바꿔도 공통으로 남는 오차"가 되어 주장이 강해진다.
단 그것도 같은 아키텍처·데이터·split이다.

### 16.7 `sigma_target = sqrt(sigma_label^2 + sigma_model^2)`는 유도가 아니라 진단이다

`status_for_gpt` §8.3(b)에서 "학습 target이 val 최적해보다 3.3배 날카롭다"고 주장했다.
**현상 진단으로는 유효하지만 target 설계의 이론적 정답으로 쓰면 안 된다.**

외부 검토의 반론: GT target은 `P(free | annotation)`이어야 하고 그것을 정하는 것은 label/world
uncertainty다. 모델이 부정확한 것을 target에 넣으면 **"못하는 모델일수록 쉬운 target"**이라는
자기강화가 생긴다. **이 반론이 맞다.** 다만 한 단계 정밀화가 필요하다 -- BCE의 최소화자는
`E[y | image]`, 즉 **입력이 주는 사후확률**이므로, 우리가 잰 `sigma_model = 0.236 m`에는 성분이
둘 섞여 있다.

| 성분 | target에 넣어야 하나 |
|---|---|
| **(i) 입력 자체의 모호성** -- 이미지가 경계를 그 이상 정하지 못하는 부분 | **넣는 것이 맞다.** Bayes 최적 예측기도 정확히 그만큼 뭉개져 있다 |
| **(ii) 모델 결함** -- 용량·최적화·**geometry 버그** | **넣으면 안 된다.** 자기강화가 여기 걸린다 |

**우리는 (i)과 (ii)를 나눌 수 없다.** 그래서 이 계산은 진단으로만 쓴다. 그리고 이것이 아래
§16.8의 순서를 정한다 -- **geometry 결함은 (ii)이므로, 고치면 0.236 m가 바뀐다.**

추가 유보: 0.236 m는 **반경** `range_mae`이고 soft boundary는 **수직** 거리다. Gaussian·zero
mean·독립 가정도 검증되지 않았다.

### 16.8 loss 연구를 여기서 닫는다 -- 다음 세션의 진입점

**`delta` 스윕은 하지 않는다.** §15.8(e)·§16.7까지 왔을 때 두 가지 때문이다.

1. `delta`의 근거가 `sigma_model = 0.236 m`인데 geometry 결함이 그 값의 일부를 만들고 있을 수
   있다(§16.7의 (ii)). **고치기 전에 스윕하면 결함에 맞춰 target 폭을 캘리브레이션한다.**
2. §16.2가 품질·안전 축은 세 loss가 전부 동일함을 보였다. `delta`가 개선할 수 있는 것은
   안정성 축뿐이고 그건 이미 8~22배 확보돼 있다.

**확정 config는 그대로 유지한다** -- `soft_boundary`, gaussian, δ=0.15, α=0.5, λ_B=0.5,
λ_R=0.3, δ_R=0.20 대칭, β=0.10. 비대칭 `δ_R+`는 **채택하지 않는다**(§13.8의 미결을 종결:
원인 분리가 안 되고 n=3에 그 칸이 없다).

다음 작업 순서는 `docs/experiment_history.md` §5에 있다.

## 17. 주장 ①을 cm로 재진술했다 -- 줄어든 것은 **편향**이고 잡음은 그대로다 (2026-08-25)

`experiment_history.md` §5 "다음 세션이 할 일" 2번을 실행한 결과다. 도구는
`tools/report_seed_jitter.py`, 근거는 `runs/ablation/ckpt/`의 체크포인트 9개
(`A_ce`·`C_soft`·`D_range` × 시드 3개), val 75프레임 × 720방향.

### 17.1 왜 했나 -- 무차원 σ는 중요한 크기인지 알 수 없다

살아남은 주장 ①은 "`fatal_rate`의 시드 간 σ가 0.0063 → 0.0007"이다. **이 숫자만으로는 그게
로봇에게 중요한 크기인지 판단할 수 없다.** 그래서 계획은 같은 사실을 cm로 옮기는 것이었다 --
"재학습하면 경계가 median X cm 흔들린다"는 안전 여유와 직접 비교되기 때문이다.

### 17.2 계획대로는 되지 않았다 -- 광선별 흔들림은 CE와 같다

프레임 `f`, 방향 `θ`, 시드 `s`의 예측 자유거리 `R̂_s(f, θ)`를 학습·평가와 **같은 함수**
(`first_free_range`)로 뽑고, 세 시드 모두 `RAY_OK`인 광선에서 시드 간 σ를 냈다.

| | `iou_free` | **σ_전역** | σ_ray median | σ_ray P90 | σ_잔차 median | 상태 불일치 |
|---|---|---|---|---|---|---|
| `A_ce` | 0.7976 | **1.75 cm** | 3.82 cm | 14.22 cm | 4.31 cm | 13.59 % |
| `C_soft` | 0.7988 | 0.57 cm | 4.33 cm | 12.58 cm | 4.29 cm | 16.39 % |
| `D_range` | 0.7977 | **0.16 cm** | 3.82 cm | 11.81 cm | 3.95 cm | 15.17 % |
| A/D 배 | — | **10.7x** | **1.0x** | 1.2x | 1.1x | — |

**광선별 σ의 median이 완전히 같다.** 계획대로 "경계가 8배 안정해진다"고 쓰면 **틀린 진술**이다 --
독자는 경계의 각 점이 8배 안정해졌다고 읽는데 그렇지 않다.

### 17.3 분해하면 화해한다 -- 두 가지가 같은 이름으로 불렸다

`R̂_s(f,θ) = M_s + resid_s(f,θ)`, `M_s = mean_{f,θ} R̂_s`로 나눈다.

- **σ_전역** = `std_s M_s`. 경계가 **통째로** 미는 양이다.
- **σ_잔차** = 방향마다 **독립으로** 떠는 양이다.

집계 지표(`fatal_rate`·`range_bias`)는 23,000개 광선을 평균하므로 **독립 성분은 상쇄되고
전역 성분만 남는다.** 반대로 광선별 σ는 잔차(약 4 cm)가 전역(약 2 cm)보다 커서 잔차에 지배된다.

**즉 주장 ①은 처음부터 σ_전역에 대한 것이었다.** 기존 `range_bias` σ(0.0190 → 0.0023 m
= 1.90 → 0.23 cm, 8.4배)와 여기 σ_전역(1.75 → 0.16 cm, 10.7배)이 같은 양이고 값도 맞는다.

> **정정된 진술**: 재학습하면 경계가 **전체적으로** CE는 1.75 cm, `D_range`는 0.16 cm 밀린다
> (약 9~11배). 하지만 **방향별 산포**는 median 3.8 cm / P90 12~14 cm로 **양쪽이 같다.**
> **이 loss는 재학습 흔들림의 편향 성분을 없애고 잡음 성분은 그대로 둔다.**

§16.4의 한 줄 결론("더 좋은 모델을 주지 않고 같은 모델을 더 일관되게 준다")은 유지되지만,
"일관되게"가 **어느 축에서인지**가 이제 특정됐다.

### 17.4 양자화 바닥이 아니다 (반증 시도)

`R̂`는 광선 표본 간격(기본 0.5셀 = **2.5 cm**)에 양자화된다. 시드 3개가 눈금 위에 있으면 σ의
최소 비영 값이 `2.5/√3 = 1.44 cm`이므로, "광선별 σ가 같다"가 **모델의 성질이 아니라 눈금의
성질**일 수 있었다. 간격을 5배 세밀하게(0.1셀 = **0.5 cm**) 다시 쟀다.

| step | σ_전역 (A→D) | σ_ray median (A / D) | σ=0 비율 |
|---|---|---|---|
| 0.5셀 (2.5 cm) | 1.75 → 0.16 cm (10.7x) | 3.82 / 3.82 | — |
| **0.1셀 (0.5 cm)** | 1.73 → 0.19 cm (8.9x) | **3.46 / 3.46** | 23~24 % |

**결론이 그대로다** -- median이 3.82에서 3.46으로 조금 내려갈 뿐 두 셀이 여전히 정확히 같다.
양자화 artifact가 아니다. (예측 자체가 5 cm 셀의 이진 맵이므로 간격을 더 줄여도 셀 크기가
바닥으로 남는다. `σ=0 비율` 23 %가 그 바닥의 크기다.)

### 17.5 σ가 볼 수 없는 불안정은 개선되지 않았다

**`상태 불일치`(한 시드는 격자 안에서 장애물을 보고 다른 시드는 격자 끝까지 free로 본 광선의
비율)는 13.59 % → 15.17 %로 오히려 조금 나쁘다.** 이 광선들은 σ 표본에서 **빠지므로** σ만
읽으면 안 보인다. **안정성을 주장할 때 반드시 같이 적는다** -- 빼놓으면 불안정한 config가
유리해진다(§15.6과 같은 종류의 함정이다).

### 17.6 규모 감각 -- 시드 흔들림은 오차의 주역이 아니다

같은 광선에서 GT 대비 오차는 세 셀 모두 median **15.0 cm**다. 즉

    모델 오차 15 cm  >>  방향별 시드 흔들림 3.8 cm  >>  전역 시드 흔들림 0.16 cm

**시드 분산은 오차의 주역이 아니다.** §16.6이 "현재 modeling pipeline이 공유하는 오차"라고
부른 것과 같은 그림이고, §18(아래)이 그것을 loss 계열까지 확장해 확인한다.

## 18. 공유 오차는 loss 계열을 넘어서도 남는다 -- 교차 앙상블 (2026-08-25)

`experiment_history.md` §5 4번. 도구는 `tools/report_ensemble.py`(softmax 확률 평균, τ=0.5,
학습 루프와 같은 지표 함수).

**왜 했나.** §16.6의 "공유 오차"는 시드 3개 앙상블이 `iou_free` 격차의 1.1 %만 닫는다는
실측에 근거하는데, **세 시드는 초기화와 배치 순서만 다르다.** 목적함수가 다른 모델을 섞어도
같은 자리에 멈추는지가 그 주장의 다음 시험이다.

| 구성 | 모델 수 | `iou_free` | 격차 닫음 | `f1@10cm` |
|---|---|---|---|---|
| `A_ce` 단일 평균 | 1 | 0.7976 | 기준 | 0.5503 |
| `A_ce` 시드 앙상블 | 3 | 0.8007 | +1.55 % | 0.5580 |
| `C_soft` 시드 앙상블 | 3 | 0.8017 | +2.01 % | 0.5614 |
| `D_range` 시드 앙상블 | 3 | 0.8000 | +1.19 % | 0.5499 |
| **3계열 교차 (전체)** | **9** | **0.8018** | **+2.05 %** | 0.5592 |

**목적함수가 서로 다른 9개를 다 섞어도 0.8018에서 멈춘다** -- 한 계열의 시드 앙상블(0.8017)이
이미 도달한 자리다. **초기화를 바꿔도, loss 계열을 바꿔도 같은 오차가 남는다.**

교차 검증 하나: `D_range` 시드 앙상블이 0.7977 → 0.8000(+1.19 %)인데 이는
`docs/temp/status_for_gpt_2026-08-23.md` §7.1의 임시 코드 측정(0.7977 → 0.8000, 1.1 %)과
**정확히 일치한다.** 새 도구가 기존 숫자를 재현한다.

**유보.** 여전히 **같은 아키텍처·같은 데이터·같은 split**이다. 그래서 이 결과를
`task ceiling`이라고 부르지 않는다(§16.6의 규약을 그대로 유지한다).

**작은 예외 하나**: `A_ce+C_soft` 교차가 `f1@10cm` 0.5623으로 어느 계열의 자체 앙상블보다
높다. CE와 soft 사이에 **상보적 오차가 약간은 있다**는 뜻이지만 `iou_free`로는 무시할 크기다.

## 19. `L_range`의 dead zone이 실제로 무엇을 면제하는가 (2026-08-27)

도구: `tools/diagnose_range_dead_zone.py` (테스트 `tests/tools/test_diagnose_range_dead_zone.py`).
Y=1(`runs/ablation/D_range_s0`)과 **Y=4**(`runs/height_bins/y4_s0`) 양쪽에서 재현했다.

### 19.1 왜 물었나 -- `range_arc_mae`는 상쇄 뒤의 값이다

`e_j = â(θ_j) − a_gt(θ_j)`는 광선 200표본의 **부호 있는 합**이므로, 광선 앞쪽 과대예측과
뒤쪽 과소예측이 서로 지운다. 그래서 `|e_j| ≤ δ_R`(gradient 정확히 0)이라는 조건은
**"이 방향을 맞혔다"보다 약하다.** 얼마나 약한지는 측정된 적이 없었다.

표본별 잔차를 부호로 갈라 `e_over`/`e_under`를 만들면 `e_signed = e_over − e_under`가 loss가
보는 값이고 `e_abs = e_over + e_under`가 상쇄 전 총량이다. 그 분해가
`compute_range_loss`의 `arc_hat − arc_gt`를 정확히 복원하는 것을 테스트로 고정했다.

### 19.2 상쇄는 실재하지만 실질 누수는 0.6 %다

| | Y=1 val | Y=4 val | Y=1 train | Y=4 train |
|---|---|---|---|---|
| `\|e_signed\|` (loss가 보는 값) | 0.2416 | 0.2222 | 0.0458 | 0.0467 |
| `e_abs` (상쇄 전) | 0.3034 | 0.2861 | 0.1244 | 0.1249 |
| **상쇄율** | 0.204 | 0.223 | **0.632** | **0.626** |
| dead zone 안 광선 | 60.7 % | 66.0 % | **97.4 %** | **97.3 %** |

**train에서는 loss가 실제 불일치의 37 %만 본다.** 그런데 "그래서 틀린 광선이 면제되나"를
물으면 답이 다르다. `e_abs`에는 soft target이 정당하게 설명하는 대역 폭이 섞여 있으므로
**대역 밖** 불일치로만 다시 세면:

| dead zone 안인데 실제로 틀린 광선 | Y=1 val | Y=4 val | train |
|---|---|---|---|
| 대역 밖 불일치 > 0.20 m | **0.6 %** (75개) | **0.8 %** (103개) | **0.0 %** |
| 명백한 free 섬(far 과대예측 > 0.20) | 0.1 % (8개) | 0.0 % | 0.0 % |

**상쇄 구멍은 논리적으로 실재하지만 이 모델에서 실제로 새는 것은 val 광선 2만 개 중 75~103개다.**
상쇄로 지워지는 것의 대부분이 경계 대역 안이고 거기서는 지워지는 것이 맞다.

### 19.3 val `arc_mae`가 δ_R 밑으로 안 내려오는 이유는 경계 대역이다

층별 **부호 있는** 기여 `s_b`(`Σ_b s_b = e_signed`)로 보면:

| 층 | Y=4 val `mean\|s_b\|` | **분산 몫** | Y=4 train `mean\|s_b\|` |
|---|---|---|---|
| 경계 대역 `\|d\| ≤ 0.15` | **0.1616** | **70.8 %** | 0.0311 |
| near 0.15~0.5 | 0.0604 | 26.3 % | 0.0109 |
| **far > 0.5** (설계 목적인 free 섬) | **0.0232** | **2.9 %** | 0.0168 |

두 가지가 나온다.

1. **train의 경계 대역 `mean s_b = +0.0026`(Y=1은 −0.0011)** -- 사실상 0이다.
   `y(d) + y(−d) = 1`이므로 **제자리에 있는 soft 대역은 arc에 정확히 0을 기여한다**는 것이
   실측으로 확인됐다(테스트로 고정). 즉 `δ_R`의 여유는 대역의 번짐을 흡수하는 데 쓰이지 않는다.
2. **val 오차의 71 %가 경계 대역에서 온다.** far는 분산의 2.9 %이고 train(0.0168)과
   거의 차이가 없다 -- **설계 목적이었던 "벽 뒤 free 섬"은 이미 학습됐고 일반화도 된다.**

**즉 `L_range`가 val에서 재고 있는 것은 경계 오차의 반경 방향 투영이다.** `L_B`와 같은
실패를 다른 좌표계에서 보고 있으므로 독립적인 정보를 거의 주지 않는다. `D_range`가
정확도를 못 올리고 재현성만 올린 것(§15·§16)과 앞뒤가 맞는다.

### 19.4 문서에 없던 것 둘 (이 절에서 추가)

- **비스듬한 광선.** `d`는 수직거리인데 `e_j`는 반경 방향이다. 반경 변위 = 수직 변위/cos φ이고
  `δ_R/δ = 1.333`이므로 **φ ≳ 41°로 꽂히는 광선에서는 soft 대역 안의 변위를 `L_range`가
  벌할 수 있다.** "두 항이 안 싸운다"는 보장은 거의 수직인 광선에만 성립한다.
- **`L_range`는 학습 후반에 사실상 꺼진다.** train `arc_mae`가 epoch 3에 dead zone
  안으로 들어가고(0.227 → 0.185) `share_range`가 12.9 % → 0.33 %로 떨어진다. **40 epoch 중
  실질적으로 3 epoch만 살아 있다.** 이것이 "재현성만 올리고 정확도는 안 올린다"의 메커니즘일
  수 있으나 **미검증 가설이다** -- λ_R을 앞 3 epoch에만 켠 런과 5 epoch 이후에만 켠 런
  두 개면 갈린다(스케줄 인자가 아직 없다).

## 20. 경계 target 하이퍼파라미터를 네 축으로 전부 훑었다 (2026-08-27, 사용자 요청)

**사용자 질문에서 출발했다: "`L_B`가 수렴하지 않는데 최소한 수렴은 해야 정상 아닌가.
아니면 이걸 뺀 게 더 낫지 않나."** 그 질문이 §16.8이 닫은 축(`δ` 스윕)을 다시 열었다 --
§16.8은 `δ`를 **안정성** 손잡이로만 취급하고 닫았는데 §10.1은 `δ`를 **수렴** 손잡이라고
부른다. 즉 이 질문은 그때 물어진 적이 없다.

전부 **Y=4, 시드 1개, 40 epoch**이고 나머지는 확정 config다(λ_B=0.5, λ_R=0.3, δ_R=0.20,
β=0.10). 런은 `runs/alpha_y4`, `runs/loss_convergence`. 스크립트는
`configs/sweep_soft_alpha_y4.sh`, `sweep_band_kappa.sh`, `sweep_label_eps.sh`,
`sweep_delta_only.sh`.

> **시드가 1개이므로 이 절의 표는 순위 확정용이 아니라 곡선의 모양을 읽는 용도다.**
> 같은 config·같은 시드 두 런(`a050_s0` 대 `y4_s0`)의 재현 노이즈가 `kl_boundary` 상승폭
> **0.0017**, 총 loss 상승폭 **0.0069**다. 품질 지표는 σ_run(`f1@10cm`) = 0.0037(§13.6.1).

### 20.1 **[방법론 정정] `kl_boundary`는 config끼리 비교할 수 없다**

**이 절에서 가장 중요한 것이다.** `kl_boundary`는 각 런이 **자기 `Ω_B`에서 자기 target에
대해** 잰 평균이다. 그래서 손잡이를 바꾸면 값이 줄어드는데, 그 줄어듦의 상당 부분이
**재는 대상이 쉬워진 것**이다.

- **`δ`가 커지면 셀 집합이 바뀐다.** δ=0.45의 `Ω_B`는 셀의 32 %이고 벽에서 40 cm 떨어진
  셀까지 들어오는데 거기 target은 0.958이라 쉽다. δ=0.15의 `Ω_B`는 9.8 %이고 전부 어렵다.
- **`α`·`κ`·`ε`이 바뀌면 target이 바뀐다.** 평평한 target은 본질적으로 맞히기 쉽다.

δ=0.45 런의 `kl_boundary` 0.0870을 분해하면

    0.0870  →  0.1052 (셀 집합을 |d| ≤ 0.15로 통일)  →  0.2691 (target도 공통으로 통일)

이고 대조군은 같은 눈금에서 0.4780이다. **"96 % 개선, 사실상 수렴"으로 처음 보고했던 것이
실제로는 44 %다.** `H̄`(상수 하한, §7.1)는 이미 처리하고 있었는데 이 둘을 놓쳤다.

**정본 지표는 `tools/report_boundary_calibration.py`의 `공통 kl`이다** -- 모든 런의 최종
체크포인트를 **같은 셀**(`|d| ≤ 0.15`)에서 **같은 target**(δ=0.15, α=1.0, κ=1, ε=0)에 대해
채점한다. 그 눈금은 **대조군에게 유리하다**(공통 target이 대조군 자신의 것이다). 그런데도
대조군이 꼴찌이므로 개입들의 개선은 실재하고 오히려 과소평가된 값이다.

### 20.2 축 1 -- `α`(모양)는 포화한다

| α | `kl_boundary` 상승폭 | `f1@10cm` | `iou_free` 최고 | std(ε) 함의 |
|---|---|---|---|---|
| 0.25 | +0.4463 | 0.6098 | 0.8099 | 3.7 cm |
| 0.50 (확정) | +0.2078 | 0.6035 | 0.8122 | 6.6 cm |
| **1.00** | **+0.1684** | 0.5974 | 0.8118 | 8.1 cm |
| 3.00 | +0.1741 | 0.5973 | 0.8116 | 8.6 cm |
| 5.00 | +0.1696 | 0.6024 | 0.8106 | 8.6 cm |
| ∞ (선형) | +0.1700 | 0.5992 | 0.8122 | 8.7 cm |

**α ≥ 1.0은 전부 평평하다** -- 구조적이다. 이 계열이 함의할 수 있는 경계 오차 표준편차의
**상한이 `δ/√3` = 8.7 cm**(선형 극한)이고 α=1.0에서 이미 8.1 cm(상한의 93 %)다. 무한대로
키워도 0.6 cm를 더 못 넓힌다. **`δ`가 천장이고 `α`는 그 밑에서만 움직인다.**

그리고 이 천장이 문제다. 실측 특징맵 해상도가 **1~2 m에서 10.5 cm, 3~4 m에서 20~24 cm**
(`tools/report_f1_by_range.py`)이므로 **1 m를 넘으면 가장 평평한 target조차 입력보다
날카롭다.** BCE의 최소화자는 `E[y|image]`이므로 Bayes 최적 예측기도 그만큼 뭉개져 있고,
따라서 val KL에 0이 아닌 하한이 있다.

> **[정정] §10.3의 α=0.5 채택 근거는 지금 남아 있지 않다.** 근거였던 `f1@10cm`
> 0.5491 > 0.5470(α=1.0)의 차이 0.0021은 σ_run 0.0037의 0.57배이고, §13.6.1이 이미
> 기각했다. Y=4 재측정에서도 α=0.5가 f1 0.6035, α=1.0이 0.5974로 **1.6σ**다 --
> 부호는 같지만 유의하지 않다. **α는 미결로 남는다**(n=3이 필요하다).

### 20.3 축 2 -- `δ`(폭)는 되지만 기하를 먹는다

`α=1.0, κ=1, ε=0` 고정. **공통 눈금 기준.**

| δ | `kl_boundary` 상승폭 | **공통 kl** | 예측 엔트로피 | `f1@10cm` | `iou_free` 최고 |
|---|---|---|---|---|---|
| 0.10 | +0.4415 | 0.5644 | 0.2853 | **0.6025** | 0.8106 |
| **0.15 (확정)** | +0.1684 | 0.4780 | 0.3386 | 0.5974 | 0.8118 |
| **0.20** | +0.0789 | **0.3862** (−19 %) | 0.4162 | 0.5933 | 0.8139 |
| **0.25** | +0.0382 | **0.3299** (−31 %) | 0.4768 | 0.5951 | **0.8151** |
| 0.30 | +0.0186 | 0.3019 (−37 %) | 0.5196 | 0.5924 | 0.8126 |
| 0.45 | +0.0074 | 0.2691 (−44 %) | 0.5928 | **0.5754** ✗ | 0.8103 |

**δ ∈ [0.20, 0.25]가 실용 구간이다** -- 공통 눈금 19~31 % 개선에 품질이 전부 잡음 안이고
`iou_free`는 오히려 최고값이다. 확실히 나빠지는 것은 δ=0.45뿐이다(`f1@10cm` −0.0220 = **5.9σ**).

**층별로 보면 왜 거기가 한계인지 보인다.** 바깥층이 U자이고 최저가 δ=0.15~0.20이다.

| `\|d\|` 층 | δ0.10 | δ0.15 | δ0.20 | δ0.25 | δ0.30 | δ0.45 |
|---|---|---|---|---|---|---|
| 5~8 cm | 0.723 | 0.585 | 0.428 | 0.322 | 0.260 | 0.169 |
| 8~12 cm | 0.527 | 0.448 | 0.362 | 0.311 | 0.285 | 0.254 |
| **12~15 cm** | 0.367 | **0.350** | **0.351** | 0.366 | 0.388 | **0.441** |

그 너머로는 경계 옆을 사려고 바깥을 판다.

**[물리적 해석 -- δ 확대를 채택하지 않는 이유]** δ=0.45는 통로 한가운데 셀(자유 셀
`d` 중앙값 0.316 m)에 **target 0.879**를 준다. target의 유도가 `ε ~ N(0, σ²)`이므로 이는
**"진짜 경계가 ±45 cm 안 어딘가에 있다"**는 주장이고, 통로 폭 중앙값이 63 cm인 이 데이터에서는
**"벽이 통로 한가운데 있을 수도 있다"**는 뜻이다. 라벨러가 아는 것과 어긋난다. 그리고
**자유 셀의 절반이 벽에서 32 cm 이내**(val 75프레임 실측)라 기하 비용이 크다:

| δ | hard free로 남는 자유공간 | hard free가 **전혀 없는** 프레임 |
|---|---|---|
| 0.15 | 74.8 % | 0.0 % |
| 0.20 | 67.0 % | 0.0 % |
| 0.30 | 51.4 % | 0.0 % |
| 0.45 | **31.1 %** | 0.0 % |
| 0.60 | 19.1 % | **28.0 %** |

**`L_range`가 그것을 보완하지 못한다**(실측): δ 0.15 → 0.45에서 `range_arc_mae`
0.2251 → 0.2319, `range_missed_obstacle_rate` 0.0372 → **0.0455(+22 %)**로 **자기 지표가
같이 나빠진다.** 광선당 스칼라 하나에 20 cm dead zone이라 셀 단위 감독을 대신할 수 없다(§19).

### 20.4 축 3 -- `κ`(대역 수축)는 실패한다, 그리고 그 실패가 원인을 짚어 준다

`y' = κ·y + (1−κ)/2`. 대역 폭을 안 건드리므로 통로 기하가 안전하다. 구현은
`soft_boundary.apply_kappa`, 플래그 `BAND_KAPPA`/`--band_kappa`, 기본 1.0(항등).

| κ | `kl_boundary` 상승폭 | `f1@10cm` | `iou_free` 최고 |
|---|---|---|---|
| 1.00 | +0.1684 | 0.5974 | 0.8118 |
| **0.80** | **+0.1184** | 0.5955 | 0.8121 |
| 0.60 | +0.1279 | 0.5983 | 0.8125 |
| 0.40 | +0.1651 | 0.5988 | 0.8134 |
| 0.20 | **+0.2133** ✗ | 0.5979 | 0.8114 |

**U자다.** κ=0.8에서 30 % 줄었다가 다시 오르고 κ=0.2는 대조군보다 나쁘다. 이유가 둘이다.

1. **target을 0.5로 보내면 확신 있는 예측에 대한 KL이 오히려 커진다.** κ → 0 극한에서
   `KL = −log 2 − ½ log(p(1−p))`이고 `p`가 0/1에 가까울수록 발산한다. 평평한 target은
   "너도 반드시 불확실해야 한다"는 요구이기 때문이다.
2. **모델이 target을 안 따라온다.** target 평탄도가 사실상 같은 두 config를 비교하면
   (κ=0.4의 target 엔트로피 0.652 대 δ=0.45의 0.658) 모델-target 격차가 각각 **−0.142**와
   **−0.065**이고, δ 쪽만 수렴한다.

**차이는 대역 밖이었다.** `Ω_F`의 예측 엔트로피가 κ로는 0.079 → 0.109인데 δ=0.45에서는
**0.260(3.3배)**이다. **대역은 셀의 9.8 %인 얇은 띠라 양옆 hard 영역의 확신을 물려받는다.**
즉 **δ=0.45가 수렴한 것은 target을 평평하게 해서가 아니라 hard 감독의 비중을 바꿔
(`Ω_F` 13.6 % → 6.3 %) 전역 확신을 낮췄기 때문이다.**

### 20.5 축 4 -- `ε`(전역 평활)이 가장 싸게 산다

`Ω_F`는 `1−ε`, `Ω_N`은 `ε`, 대역은 `ε + (1−2ε)y`. **대역 항이 정확히 `κ = 1−2ε`인 것이
핵심**이다 -- 정규화된 target이 `y(±δ) = 1/0`을 주므로, `ε`을 hard 영역에만 걸면 대역 끝이
바로 옆 hard 영역보다 **더 확신에 찬 거꾸로 된 불연속**이 생긴다. 구현은
`compute_soft_boundary_loss(eps=)`, 플래그 `LABEL_EPS`/`--label_eps`, 기본 0.0(항등).

| ε | `kl_boundary` 상승폭 | **공통 kl** | 예측 엔트로피 | `f1@10cm` | `iou_free` 최고 |
|---|---|---|---|---|---|
| 0 (대조군) | +0.1684 | 0.4780 | 0.3386 | 0.5974 | 0.8118 |
| 0.02 | +0.0811 | 0.3636 (−24 %) | 0.3861 | 0.6025 | 0.8120 |
| 0.05 | +0.0461 | 0.3053 (−36 %) | 0.4398 | 0.6030 | 0.8115 |
| **0.10** | +0.0284 | **0.2566 (−46 %)** | 0.5060 | **0.5985** | 0.8108 |
| 0.20 | +0.0144 | 0.2348 (−51 %) | 0.5866 | **0.5609** ✗ | **0.8052** ✗ |
| *(참고)* δ=0.45 | +0.0074 | 0.2691 (−44 %) | 0.5928 | 0.5754 ✗ | 0.8103 |

**ε=0.10이 δ=0.45를 이긴다** -- 공통 kl이 낮고(0.2566 대 0.2691) `f1@10cm`이 온전하며
(0.5985 대 0.5754) **기하를 하나도 안 건드린다.** ε=0.20은 선을 넘는다(f1 −9.9σ).

`ε`의 두 가지 뜻: **통계적으로는** "라벨이 뒤집힌 비율", **기계적으로는** 모델 출력이
`[ε, 1−ε]`에 갇히므로 **확신의 천장**이다. δ와 마찬가지로 데이터에서 추정할 수 없다.

> **유보 -- `Ω_N`의 `ε`은 뜻이 다르다.** `Ω_N`(셀의 76.6 %)은 **93.3 %가 vis=0**(벽 뒤,
> raycast가 정한 것)이고 사람이 라벨한 obstacle은 **0.0 %**다(전부 대역 안에 있다). 거기서
> `ε`은 어노테이션 오류율이 아니라 **"벽 뒤가 ε 확률로 free다"**라는 거짓이고 `fatal`
> 방향의 주장이다. 대칭으로 둔 것은 검정하려는 가설의 확신 76.6 %가 거기 있기 때문이고,
> **비대칭(`ε_N`을 따로)이 다음 수다.**

> **`fatal` 개선을 안전 개선으로 읽으면 안 된다.** ε=0.10에서 `fatal` 0.1191 → 0.1139인데
> `free_miss`가 0.0867 → 0.0946으로 같이 나빠진다. **동작점 이동**이고 §16.2가 이미
> 철회한 패턴이다. 판정하려면 threshold sweep이 필요하다.

### 20.6 경계 구조는 확률 보정에만 기여한다 (대조군)

`e010_nob`: `ε=0.10`에 **`δ → 0`**(`DELTA_M=0.001`)으로 `Ω_B`를 비워 **경계 구조만 정확히
제거한** 판본이다. 코드 변경 없이 만들어진다.

| ε=0.10 | 공통 kl | `f1@10cm` | `iou_free` 최고 |
|---|---|---|---|
| **대역 있음** | **0.2566** | 0.5985 | 0.8108 |
| **대역 없음** | **0.3623** | 0.5973 | 0.8097 |

**답이 둘로 갈린다.** 확률 보정에서는 경계 구조가 **개선의 절반을 만든다**(ε 단독 −24 %,
대역을 더하면 −46 %). 결정 품질에서는 **차이가 안 보인다**(둘 다 σ 안). §16.2가 "품질·안전
축은 세 loss가 전부 동일"이라고 한 것과 같은 이야기다.

**논문 문장: "경계 구조는 확률 보정을 절반 개선하지만 결정 품질은 바꾸지 않는다."**

### 20.7 네 축이 전부 하나의 축으로 붕괴한다 -- **이 절의 결론**

12개 런(δ 6 + ε 4 + κ 1 + 경계제거 1)을 놓고 보면

> **공통 kl과 모델의 예측 엔트로피의 상관 `r = −0.901`, `R² = 0.81`**

**경계 보정 개선의 81 %가 "모델이 얼마나 덜 확신하게 됐는가" 하나로 설명된다.** 어떤
손잡이를 돌렸는지는 거의 무관하다. 잔차는 ε 계열이 일관되게 −0.046~−0.057로 회귀선 아래인데
(같은 엔트로피에서 조금 더 낫다) 그 이득은 전체 폭의 12 % 수준이다.

그리고 **능력은 따라오지 않는다.**

| | 예측 엔트로피와의 상관 |
|---|---|
| 공통 kl | **r = −0.901** |
| `f1@10cm` | **r = −0.706** (덜 확신할수록 **나빠진다**) |
| `iou_free` | **r = −0.253** (사실상 무관, 전부 0.805~0.815) |

**`val/train` 배율은 어느 config에서도 거의 안 움직인다** -- 대조군 26.7배, ε=0.05 25.3배,
ε=0.10 22.7배, δ=0.45 12.9배. train KL은 전부 0.008~0.019로 사실상 0이다. **암기는 그대로다.**

**곡선의 모양은 실제로 바뀐다.** 대조군은 조기 최저 후 끝까지 오르지만(ep10 → ep39에서
**+0.0760**) ε=0.10은 ep6쯤 올라간 뒤 멈춘다(ep10 → ep39에서 **+0.0034**, 진동 폭 6 %는
val 75프레임의 epoch 잡음). 즉 **"발산이 멈춘다"는 실재하는 개선이다.**

### 20.8 결론 -- 세 문제는 서로 다른 문제였다

| 문제 | 고쳐졌나 |
|---|---|
| val loss가 끝없이 오른다 | **예** (ε=0.10에서 ep6 이후 평평) |
| 확률 보정이 나쁘다 | **부분적** (공통 눈금 −46 %) |
| **경계를 10 cm 안에서 못 맞힌다** | **아니오** (`f1@10cm` 0.5974 → 0.5985) |
| **train 경계를 외운다** | **아니오** (val/train 23배 그대로) |

**한 문장: 모델이 경계를 더 잘 알게 된 것이 아니라, 모른다는 것을 더 정직하게 말하게 됐다.**

> 경계 항의 target 하이퍼파라미터를 네 축(모양 α, 폭 δ, 대역 수축 κ, 전역 평활 ε)으로 전부
> 훑었다. 넷 다 **모델을 덜 확신하게 만드는 한 가지 일**만 하고(R² = 0.81), 그 대가로 확률
> 보정이 최대 44~51 % 개선된다. 그러나 `iou_free`는 엔트로피와 무관하고(r = −0.25)
> `f1@10cm`은 오히려 음의 상관(r = −0.71)이다. 더 밀면(δ ≥ 0.45, ε ≥ 0.20) 정밀도를 내준다.
> **남은 병목은 loss 바깥에 있다.**

**§16.8이 loss 연구를 닫은 판단은 옳았고, 이 절은 그 판단의 정량적 근거다.**

### 20.9 확정 config는 바뀌지 않는다 -- 그리고 남은 것

**지금 확정 config를 바꿀 근거가 없다.** δ=0.15는 `f1@10cm` 최고 근처이고 바깥층 보정도
최저다. 굳이 고르면 δ=0.20~0.25 또는 ε=0.05~0.10이 "보정 20~46 % 개선, 품질 잡음 안"인데,
**확률을 그대로 쓰는 하류 작업(예: 확률 기반 planner)이 없으면 실익이 없다.**

남은 것:

1. **시드 3개.** 이 절 전체가 n=1이다. 채택 판단에는 n=3이 필요하다.
2. **`δ` 추가 실험**(사용자 요청, 별도 `runs/` 폴더). 이 절의 δ 곡선은 α=1.0에서 잰
   것이므로 확정 config(α=0.5)에서의 재확인이 그중 하나다.
3. **`ε_N`을 따로 둔 비대칭 판본** -- `Ω_N`의 93.3 %가 vis=0이라 대칭 `ε`은 거기서 거짓이다.
4. **`λ_R` 구간 스케줄**(§19.4의 미검증 가설).
5. **`f1@10cm` 천장이 입력 해상도인지 확인** -- `tools/report_f1_by_range.py`를 Y=4에서
   돌린 적이 없다. §20.2가 제시한 해상도 수치와 거리별 `f1`을 대조하면 된다.

## 21. 손잡이를 $(\sigma, k)$로 다시 세우고 $\sigma = 0.10$ / $\delta = 0.30$을 확정했다 (2026-08-28, 사용자 요청)

§20이 남긴 것은 "경계 항 `L_B`의 val 발산을 네 축 어느 것도 못 고쳤다"였다. 이 절은 그 뒤를
잇는 **52런**의 기록이고, 결론은 **손잡이 자체를 잘못 잡고 있었다**는 것이다.

### 21.1 "val loss가 조기 수렴 후 발산 = 과적합"은 성립하지 않는다

사용자 관찰은 "δ가 작으면 loss가 일찍 바닥을 찍고 계속 오른다 → 과적합"이었다. **그 바닥의
모델이 최선인지**를 재면 반박된다.

| δ (α=1.0) | 경계 KL 최저 ep | 거기 `iou_free` / `f1@10cm` | 끝(40ep) | KL 상대 상승 |
|---|---|---|---|---|
| 0.10 | 2 | 0.7779 / 0.5144 | 0.8094 / **0.6025** | +97.5 % |
| 0.15 | 2 | 0.7775 / 0.5169 | 0.8114 / 0.5974 | +48.2 % |
| 0.25 | 4 | 0.7939 / 0.5659 | 0.8142 / 0.5951 | +18.4 % |
| 0.30 | 4 | 0.7925 / 0.5678 | 0.8117 / 0.5924 | +11.2 % |
| 0.45 | 16 | 0.8080 / 0.5739 | 0.8091 / 0.5754 | +8.3 % |

**경계 KL로 early stopping을 걸면 epoch 2를 집는다.** 80 epoch 런은 더 극단적이다 — KL 최저가
epoch 1이고 거기 `f1@10cm`이 0.4002, epoch 80에서 KL은 +87 %인데 `f1`은 0.6141이다.

기제는 구조적이다. 학습 초기 모델은 경계에서 ≈0.5를 뱉고 대역 target의 평균도 ≈0.5이므로
**아무것도 모르는 모델이 대역에서 정의상 좋은 점수를 받는다.** 이후 상승은 모델이 결단을
내리기 시작한 것이고, log-loss가 확신에 찬 오답을 초선형으로 벌하는 것이다. 주기 체크포인트로
직접 확인했다(공통 눈금, δ=0.15):

| epoch | 10 | 20 | 30 | 40 |
|---|---|---|---|---|
| 공통 kl | 0.4381 | 0.4729 | 0.4912 | 0.5010 |
| **예측 엔트로피** | 0.3656 | 0.3405 | 0.3344 | **0.3307** |
| 5~8 cm 층 | 0.515 | 0.576 | 0.605 | **0.620** |
| 12~15 cm 층 | 0.356 | 0.352 | 0.355 | 0.358 |

상승이 **전부 경계 바로 옆 층**에 몰려 있고 엔트로피가 단조로 떨어진다. δ=0.30에서는
엔트로피가 40 epoch 내내 0.5201 → 0.5196으로 **거의 안 움직인다** — 평평한 target이 확신의
**상한**으로 작동한다.

**진짜 과적합 지표로 보면 어느 δ에도 과적합이 없다.** val `iou_free`의 정점→끝 변화가
−0.0004 ~ −0.0012로 전부 잡음이다. 암기 격차(train−val `iou_free`)만 0.180 → 0.148로 단조
감소한다 — 실재하는 정규화 효과지만 loss 곡선이 암시하는 크기(KL 상승폭 12배 차이)보다
훨씬 작다.

**단, 총 loss로 보면 사용자 관찰에 정당한 부분이 있다.** δ가 크면 **loss 최저점이 품질
정점과 겹쳐서 모델 선택 신호로 쓸 수 있다.**

| δ | 0.10 | 0.15 | 0.20 | 0.25 | 0.30 | 0.45 |
|---|---|---|---|---|---|---|
| 총 loss 최저 ep | 4 | 4 | 8 | **23** | **38** | 34 |
| `iou_free` 정점 ep | 16 | 23 | 27 | **27** | **34** | 25 |
| 어긋난 폭 | 12 | **19** | **19** | **4** | **4** | 9 |

### 21.2 $\alpha$를 고정한 $\delta$ 스윕은 두 효과를 섞고 있었다

§20과 §21.1의 δ 스윕은 전부 $\alpha = 1.0$ 고정이다. $\sigma = \alpha\delta$이므로 **δ를
키울 때 σ가 같이 커진다.** "대역을 넓힌 효과"와 "target을 뭉갠 효과"가 분리된 적이 없었다.

$\delta$를 고정하고 $k = \delta/\sigma$만 올리면 갈린다:

| 같은 δ, k만 다름 | σ | k | σ_ray med | 상태 불일치 | `iou_free` |
|---|---|---|---|---|---|
| δ=0.25 | 0.25 | 1 | 5.00 cm | 28.2 % | 0.8118 |
| δ=0.25 | 0.125 | **2** | **4.47 cm** | **25.0 %** | **0.8134** |
| δ=0.30 | 0.30 | 1 | 5.48 cm | 30.0 % | 0.8121 |
| δ=0.30 | 0.15 | **2** | **4.87 cm** | **27.5 %** | 0.8131 |

**대역 폭을 그대로 두고 k만 올리면 두 경우 모두 좋아진다.** §20이 "δ를 넓히면 재현성이
나빠진다"고 읽은 것은 실은 **"σ를 키우면 나빠진다"**였다.

$\alpha$가 해석되지 않던 이유도 여기 있다. $\alpha$는 **양 끝이 막힌 모양 손잡이**다 —
$\alpha \to 0$이면 step, $\alpha \to \infty$이면 **선형**(대역 안 균등)이고 그 이상은 없다.
$\alpha = 1.0$에서 이미 선형까지 97 % 와 있다(§6.3). 반면 $\delta$는 무계한 척도다. 게다가
$k = 1/\alpha$가 작으면 절단이 $\sigma$를 갉아먹는다 — 명세 §6.2의 표.

### 21.3 재현성은 **실효 산포**가 지배한다

$\mathrm{d}y/\mathrm{d}d$의 표준편차를 실효 산포라 부른다. **모델은 σ도 δ도 아닌 이 값에
반응한다.** 시드 5개짜리 10개 config:

### 21.4 넓은 대역이 곧 흐릿한 감독은 아니다

"완전 hard"만 세면 δ=0.30에서 자유 셀 보존율이 74.8 % → 51.4 %로 반토막이지만, **σ가 작으면
대역 바깥쪽은 사실상 hard**다:

| config | δ | 완전 hard | y ≥ 0.95 | **y < 0.90 (진짜 흐림)** |
|---|---|---|---|---|
| σ0.15 k1 (옛 확정) | 0.15 | 74.8 % | 81.4 % | **18.6 %** |
| **σ0.10 k3 (확정)** | 0.30 | 51.4 % | 73.3 % | **18.6 %** |
| σ0.08 δ0.30 | 0.30 | 51.4 % | 81.4 % | **16.7 %** |
| σ0.30 k1 | 0.30 | 51.4 % | 57.7 % | **36.1 %** |

**δ를 두 배로 넓혀도 진짜 흐릿한 셀은 18.6 %로 같다.** 맨 아래 행이 대조군이다 — 같은 δ에서
σ만 키우면 36.1 %로 두 배가 된다. **흐릿함을 만드는 것은 δ가 아니라 σ다.**

통로 중심은 벽에서 median 95.5 cm(P10 53 cm) 떨어져 있어 δ=0.30 바깥이고, δ=0.30에서 hard
free 셀이 하나도 없는 프레임은 val 75개 중 **0개**다.

### 21.5 $\delta \le \delta_R$은 불필요한 제약이었다

soft target이 $y(d) + y(-d) = 1$로 대칭이라 **적분한 `arc`의 기댓값이 GT와 같다.** 따라서
완벽히 보정된 모델은 대역 폭과 무관하게 $e = 0$이고 dead zone과 겹쳐도 안 싸운다. 실측:

| config | δ | val `loss_range` | `arc_mae` | `arc_bias` |
|---|---|---|---|---|
| 옛 확정 | 0.15 | 0.0867 | 0.2251 | +0.0808 |
| `s080k3` | 0.24 | 0.0878 | 0.2261 | +0.0833 |
| `s100k3` | **0.30** | 0.0871 | 0.2259 | +0.0826 |

$\delta_R = 0.20$은 그대로 둔다. §19에서 진단한 대로 이 항은 40 epoch 중 약 3 epoch만
실질적으로 살아 있다.

### 21.6 확정: $\sigma = 0.10$ m, $\delta = 0.30$ m ($k = 3$)

**$\delta$는 사용자가 기하로 정했다** — "경계가 통로 중앙까지 튀어나올 일은 없으므로 30 cm를
넘는 일은 절대 없다." 이 프로젝트에서 스윕이 아니라 **물리적 근거로 정해진 유일한 경계
하이퍼파라미터**이고, §21.4의 통로 여유 측정과 일치한다.

**$\sigma$는 데이터가 못 정한다.** 재현성만 보면 $\sigma \to 0$이 이기는데 그건 hard 라벨
(=CE)과 같아 soft target을 쓰는 의미가 사라진다. 데이터가 준 것은 경계선 둘뿐이다.

- $\sigma \le 0.15$ — $\sigma$=0.175, 0.20에서 `f1@10cm`이 0.5835 / 0.5858로 무너진다.
- $\delta \le 0.30$ — δ=0.45(`s150k3`)는 `f1@10cm`의 시드 간 σ가 **0.0118**로 다른 config
  (0.003~0.006)의 2~4배다. k를 키워도 못 구한다.

**$\sigma = 0.10$을 고른 이유는 해석 용이성이다**(사용자 판단). $k = 3$이 정확히 떨어져
실효 산포 $\simeq \sigma$이므로 "$\sigma = 10$ cm"가 문자 그대로 10 cm를 뜻한다. target을
문장으로 옮기면:

> "라벨 경계는 보통 6.7 cm 어긋나 있고, 68 %는 10 cm 이내, 87 %는 15 cm 이내, 96 %는
> 20 cm 이내이며, **30 cm를 넘는 일은 절대 없다.**"

옛 확정값은 같은 문장으로 *"보통 6.6 cm, 73 %는 10 cm 이내, **15 cm를 넘는 일은 절대 없다**"*
였다. 중앙은 거의 같고 **꼬리 하나가 다르다** — 사용자가 15 cm 절벽을 단정할 수 없다고 판단한
것이 채택 근거다.

**옛 확정값 대비 득실** (전부 시드 5개):

| | 옛 확정 (σ0.15 k1, δ0.15) | **확정 (σ0.10 k3, δ0.30)** |
|---|---|---|
| `iou_free` | 0.8113±0.0018 | 0.8124±0.0015 |
| `f1@10cm` | 0.6051±0.0053 | 0.6030±0.0057 |
| `fatal_rate` | 0.1204±0.0032 | 0.1201±0.0015 |
| σ_ray median | 4.47 cm | 4.47 cm |
| σ_ray P90 | 14.08 cm | **13.39 cm** |
| **상태 불일치** | **21.91 %** | 25.45 % |
| loss 최저 ↔ 품질 정점 | 4 ↔ 23 (19 어긋남) | **16 ↔ 16** |

**지는 항목은 상태 불일치 하나뿐이고, 3.54 %p는 잔차 잡음(1.27 %p)의 2.8배로 실재한다.**
논문에 쓸 때 숨기지 말고 한계로 적시할 것:

> δ = 3σ = 0.30 m는 라벨 상한을 정직하게 반영하지만, 경계 항이 평균 내는 집합에 쉬운 셀이
> 섞여 경계 근처 신호가 묽어진다($\Omega_B$ 중 $\lvert d\rvert<10$ cm 비중 40.7 % → 21.1 %).
> 그 결과 재학습 간 장애물 유무 불일치가 21.9 % → 25.5 %로 늘어난다.

**더 나은 재현성을 원하면 `s080k3`(σ=0.08, δ=0.24)가 옛 확정값을 세 지표 모두에서 이긴다**
(4.18 / 13.04 / 21.05 %). 채택하지 않은 이유는 δ=0.24가 사용자가 방어할 수 있는 값이
아니기 때문이다 — 24 cm 상한은 30 cm보다 센 주장인데 근거가 없다.

### 21.7 이 절이 쓰지 않은 것 / 다음 후보

- **$\alpha$ 격자는 더 볼 필요 없다.** $\delta$와 한 축(전이폭)을 공유하고, 사전 등록한
  예측 세 개가 3 % 안으로 맞았다(§20의 후속). $\alpha$는 $1/k$로 유도되는 값이다.
- **$\kappa$·$\varepsilon$은 기각 상태 그대로다**(§20.4, §20.5). 코드에 남아 있지만
  기본값이 꺼짐이고 예전과 bit 동일이다.
- **80 epoch는 채택하지 않았다.** `OneCycleLR`이 `num_epochs`에 묶여 있어 40 → 80은 "더 돌린
  것"이 아니라 다른 lr 궤적이다(`train_robot_bev.py:613`). δ=0.15에서 `f1@10cm`이
  0.5974 → 0.6141로 올랐지만 δ=0.30에서는 +0.0015로 잡음이라, **스케줄 효과이지 δ 효과가
  아니다.** 이걸 쓰려면 스케줄 자체를 따로 검증해야 한다.
- **미결**: 확정 config에서 $\delta_R^{+}$ 비대칭(§8.6), 상태 불일치 자체를 낮추는 방법
  (지금은 어떤 config에서도 21 % 아래로 안 내려간다).

### 21.8 재현 방법

```bash
# 실험 스크립트 (전부 runs/ 별도 폴더, 시드 0이 있으면 심링크로 재사용)
bash configs/sweep_delta_alpha.sh      # δ×α 격자, 80 epoch 계열   -> runs/delta_alpha
bash configs/sweep_delta_seeds.sh      # δ 시드 반복 (α=1.0)        -> runs/delta_seeds
bash configs/sweep_sigma_k.sh          # (σ,k) 계열 + 시드 반복     -> runs/sigma_k

# 집계 -- **config끼리 비교는 공통 눈금으로만 한다(§20.1)**
python tools/report_seed_jitter.py --log_root=runs/sigma_k \
    --cells=s080k3,s100k2,s100k3,s125k2 --seeds=0,1,2,3,4
python tools/report_boundary_calibration.py --runs=<런 디렉터리 콤마 목록>
python tools/report_alpha_convergence.py --log_root=runs/sigma_k
```

`report_boundary_calibration.py`와 `report_alpha_convergence.py`는 `SIGMA_M`으로 지정한 런에서
`sigma_alpha`가 `None`이라 죽던 것을 고쳤다. 표 이름도 `σ0.1 k3 δ0.30` 형태로 바꿔
**"몇 σ에서 자르는가"가 바로 읽히게** 했다.
