# 공통 지표 정의와 보고 규칙

논문 최종 실험 전체가 쓰는 지표다. 실험별 문서는 여기를 가리키고 정의를 반복하지 않는다.

---

## 1. 지표 정의

> **[2026-10-02] 지표를 바꿨다(사용자 확정).** 이 폴더(`docs/99_paper_results/`)의 CSV는 전부
> 이 정의로 나왔다(캠페인 v3, 2026-10-03). 옛 패키지 `docs/paper_package/`는 옛 지표
> (`fatal_rate`·`free_miss_rate`·`occupied_f1_{10,20,40}cm`·`range_*`)라 숫자를 섞지 않는다. 수식·집계 규칙은
> [`evaluation_protocol.md`](evaluation_protocol.md) §4~§5, 코드 정본은
> `projects/common/metric_spec.py`.

| 지표 | 뜻 | 방향 | 논문 |
|---|---|---|---|
| **`iou_free`** | 예측한 free 영역과 정답 free 영역의 겹침 비율(IoU) | ↑ | 본문 (주 지표) |
| **constant-map baseline** | 이미지를 **보지 않고** 학습 데이터의 칸별 다수결 free 지도 하나를 통째로 답으로 내는 대조군 | 기준 | 본문 |
| **margin** | `iou_free` − baseline. **주 비교량** | ↑ | 본문 |
| **`precision`** | "갈 수 있다"고 답한 칸 중 실제로 뚫린 비율. 떨어지면 충돌로 이어진다 (옛 `fatal_rate` = 1 − precision) | ↑ | 본문 |
| **`recall`** | 실제로 뚫린 칸 중 "갈 수 있다"고 답한 비율. 떨어지면 과도한 보수성 (옛 `free_miss_rate` = 1 − recall) | ↑ | 본문 |
| **`bf_10cm` · `bf_20cm` · `bf_30cm`** | **Boundary F-measure** BF@τ. **경계 셀만** 보고, 예측 경계가 **라벨의** 경계와 τ 안에서 일치하는 정도 | ↑ | 본문 |
| `iou_non_free` | non-free 영역의 IoU. 자명해("전부 non-free")가 이미 ≈ 0.83을 받아 변별력이 낮다 | ↑ | CSV만 |
| `ring_{고리}_{위 넷}` | 거리 고리(0–1.5 / 1.5–3 / 3–4 m)마다 `iou_free`·`iou_non_free`·`precision`·`recall` | ↑ | 부록·CSV |
| `bf_{τ}_precision` · `_recall` | BF의 precision/recall — 경계가 어느 쪽으로 틀렸나 | ↑ | CSV만 |

**전부 프레임 macro다** — 프레임마다 값을 낸 뒤 프레임 평균한다. 예측과 GT가 **둘 다** 빈
프레임만 뺀다. 모든 셀 지표는 동작점 **θ = 0.5**에서 잰다(BF의 허용오차 τ와 다른 기호로 쓴다).

**뺀 것:** `range_mae`·`range_bias`·`range_missed_obstacle_rate`(방위각 자유거리 지표 전부).

## 2. constant-map baseline이 왜 필수인가

온실은 통로 배치가 규칙적이라, **이미지를 전혀 보지 않고** "여기쯤은 대체로 뚫려 있더라"
지도 하나만 외워도 `iou_free`가 0.39~0.69까지 나온다(시퀀스에 따라 다르다).

그래서 `iou_free` 값 자체는 주장이 되지 못한다. **기준선을 얼마나 이겼는지(margin)가
주장이다.** 캠페인 규칙상 baseline 없이 `iou_free`를 단독 보고하지 않는다.

기준선은 학습 스크립트가 콘솔에만 찍고 TensorBoard에 남기지 않는다. 그래서 분석 단계에서
**학습과 같은 함수**(`constant_free_map` / `iou_free`)로 다시 계산한다. 값이 갈리지 않는다.

## 3. BF@τ의 "경계"는 contour가 아니다

경계는 **ego에서 보이는 free 공간의 첫 표면**(방위각마다 광선이 처음 멈춘 셀)이다. 라벨의
관측이 ego 원점 raycast라 GT 경계가 그렇게 정의되고, 예측 경계도 같은 규칙으로 예측 free에서
유도한다. DAVIS 계열 BF는 분할 경계 전체를 쓰므로 **이름만 보고 같은 것이라 읽히지 않게**
논문에 정의를 한 줄로 적는다.

(옛 `range_bias` 부호 규약 절은 지표와 함께 뺐다.)

## 4. 보고 규칙

| 규칙 | 이유 |
|---|---|
| `iou_free`는 **항상** baseline·margin과 함께 | §2 |
| 본문 문장도 "0.81 달성"이 아니라 "상수 지도 대비 +0.29" | §2 |
| `precision`·`recall`은 **같은 동작점에서 한 쌍으로** | 문턱값을 옮기면 서로 반대로 움직인다. 하나만 좋아진 것을 "안전 개선"이라 부르면 안 된다 — 이 프로젝트에 같은 주장을 동작점 이동으로 철회한 전례가 있다 |
| BF@τ는 "라벨과의 일치도"라고 명시 | 라벨이 LiDAR + 사람 보정이다 ([`setup.md`](setup.md) §3) |
| **SD를 쓰고 SE를 쓰지 않는다** | 특히 LOSO fold는 학습 데이터를 6/7씩 공유해 독립 표본이 아니다. `SD/√7`은 표준오차가 아니다 |
| 소수 3자리, SD도 같은 자리 | 시드 SD가 0.002 수준이라 4자리는 표만 지저분해진다 |
| **마지막 epoch(100) 고정**을 프로토콜로 선언, best-epoch은 각주 | 고정 split에서 둘 차이가 `iou_free` 0.0005다(`01_overall`). 단 실험 03의 CE 칸은 다르다 — 그 REPORT 참조 |
| **유의성은 `*`로만 표시** | 시드로 짝지은 양측 t-검정의 95 % 신뢰구간이 0을 빼면 그 칸에 `*`. 지표마다 따로 검정하고 다중비교 보정은 하지 않는다. CI·p값은 `paired_differences.csv` 등에만 둔다 (`evaluation_protocol.md`) |
| 시드 산포는 SD와 **n을 함께** | n=5임을 표 각주에 |

## 5. 본문에 꼭 넣을 단서

정직하게 먼저 밝히는 편이 리뷰에서 유리하다.

- **데이터가 작다** — 전체 267 프레임, 시퀀스 7개
- **라벨이 LiDAR + 사람 보정**이라 절대 경계 오차는 측정 불가. 경계 지표는 일치도다
- **fold 간 차이의 원인이 셋**(장면 난이도 · 표본 오차 · 라벨 품질)이고 분리할 수 없다.
  fold 차이를 "모델의 일반화 능력"만으로 읽지 않는다
- **LOSO fold는 독립 표본이 아니다** — 학습 데이터를 6/7씩 공유한다

## 6. 프로토콜을 섞지 않는다

고정 split과 LOSO는 학습 데이터 크기도 묻는 질문도 다르다. **하나의 평균으로 합치거나
직접 우열을 비교하지 않는다.** 두 프로토콜의 값이 우연히 비슷해도 마찬가지다.
