# Phase 2: 학습 전(pre-training) 정렬 검증 Plan (native 어안 / Simple-BEV)

## 0. 문서의 목적과 위치

Phase 1에서 **radial_poly 투영 함수**를 검증하고 **Simple-BEV lifting에 native 투영을
통합**했다. 이제 그 통합이 정상 동작한다는 전제 하에, **실제 학습을 돌리기 직전**의
정렬 검증을 다룬다.

이 단계의 존재 이유:
> 좌표 변환이나 그리드 정렬이 틀린 채로 학습하면 **에러도 안 나고 loss도 내려가지만
> 모델은 엉뚱한 대응을 학습한다.** GPU를 며칠 돌린 뒤에야 성능 미달을 발견하고 원인을
> 못 찾는다. → **학습 한 줄 돌리기 전에** 시각화로 잡는다.

이 문서의 모든 검증은 **데이터 로더 산출물 + GT 파일만으로**(학습 불필요) 수행 가능.

### 0.1 native에서 바뀌는 점 (undistort 계획 대비)
- **입력이 어안 원본**이다. 핀홀 N뷰 개념이 없다. 카메라 = 4대 그대로.
- 검증 A의 "이미지 재투영"은 Phase 1에서 통합한 **native project()** 를 사용한다.
- 그리드 정렬(검증 B)의 본질은 **동일**(투영 모델과 무관).
- Simple-BEV는 격자점을 이미지로 투영해 특징을 샘플하므로, **BEV 격자 정의(범위·해상도)가
  모델 forward에 직접 들어간다** → 정렬이 특히 결정적.

---

## 1. 세 좌표계를 하나로 꿰는 것이 목표

```
[어안 이미지]  ◀──(검증 A)──▶  [ego 3D 좌표]  ◀──(검증 B)──▶  [BEV 격자]
 native project()/extrinsic                     Simple-BEV Vox_util(bounds, Z/Y/X)
```

- **검증 A (이미지 재투영):** 데이터에 넣는 extrinsic + native project()가 맞는가.
- **검증 B (그리드 정렬):** BEV GT와 Simple-BEV 격자가 같은 물리 공간을 같은 인덱스로
  가리키는가.

하나라도 어긋나면 loss는 돌아도 학습 내용이 틀린다(조용한 실패).

---

## 2. 사전 확정 — BEV GT의 물리적 의미 (가장 먼저)

### 2.1 해상도만으로는 부족
- 단서: SynWoodScape BEV GT는 **1024×1024**(실제 파일로 재확인). 반드시 알아야 하는 것:
  1. **커버 범위(미터):** ego 중심 기준 몇 m × 몇 m.
  2. **픽셀당 미터:** 1픽셀 = 몇 m (= 커버범위 / 1024).
  3. **ego 원점 픽셀:** ego가 이미지의 어느 픽셀(보통 중심 512,512 추정 — 검증).
  4. **축 방향:** 이미지 위쪽이 ego +x(전방)? 오른쪽이 +y? -y?

### 2.2 커버 범위 역산
```
README: BEV 카메라 z=15m 상공, pitch=-90(수직 하방), 해상도 1024×1024(가정)
커버 범위 = 2 × height × tan(FOV/2)   (핀홀 top-down 가정 시)
```
- **BEV 카메라가 어안일 가능성 배제 금지.** `_BEV` calibration이 존재. 어안 렌더면
  top-down이어도 왜곡이 있어 단순 tan 공식이 안 맞음 → 2.3 실측으로 확정.

### 2.3 실측 검증 (파라미터를 못 믿을 때)
- 알려진 3D 위치 물체(3D bbox annotation 한 객체)를 BEV GT에서 찾아, 픽셀 위치 ↔ 미터
  위치를 대응시켜 **해상도·원점 역산**. 여러 객체로 교차 확인 → 커버범위·축·원점 확정.

### 2.4 산출물
- `bev_gt_meta`: { resolution_m_per_px, coverage_range_m, ego_origin_px, axis_convention }
- 이 값이 나와야 검증 B와 Simple-BEV 격자 설정을 정할 수 있다.

## 3. 검증 A — 이미지 재투영 (extrinsic + native 투영 검증)

### 3.1 무엇을 확인하나
데이터 로더가 Simple-BEV에 넘기는 **각 어안 카메라의 extrinsic + native project()** 가
맞는지. Phase 1 층 A/C가 투영 함수·통합을 검증했으나, 데이터를 채우며 extrinsic 변환·
좌표 부호를 틀릴 수 있으므로 **학습 데이터 버전으로 재검증**한다.

### 3.2 원리
"공통 3D를 매개로 이미지와 BEV/라벨을 겹쳐본다."
```
BEV GT의 occupied 셀 (i,j)
  → bev_gt_meta로 ego 3D (x, y, z≈지면)
  → 각 카메라 extrinsic으로 카메라 좌표
  → native project()로 어안 픽셀 (u,v)
  → 그 (u,v)에 이미지 상 실제 장애물이 보이는가?
```

### 3.3 구현할 코드 (`verify_A_reprojection.py`)
- 입력: 한 샘플의 어안 4뷰, 데이터 로더의 extrinsic, native project(), BEV GT, bev_gt_meta.
- 기능:
  1. BEV GT의 occupied 경계점/대표점 추출.
  2. 각 점 → ego 3D → 각 카메라 어안 픽셀로 native 투영.
  3. 투영점을 어안 이미지 위에 오버레이 저장.
  4. (역방향 교차) 이미지 semantic 라벨 물체 픽셀을 depth로 3D화 → BEV에 찍어 GT와 겹침 확인.
- 출력: 뷰별 오버레이(사람이 눈으로 확인).

### 3.4 합격 기준
- BEV 장애물 투영점이 이미지 속 실제 장애물 위에 얹힌다.
- 전방 물체가 FV에, 좌측 물체가 MVL에 옳은 위치로 나타난다.
- 어긋나면: extrinsic 변환 또는 좌표 부호(CARLA 규약) 오류.

## 4. 검증 B — 그리드 정렬 (BEV GT ↔ Simple-BEV 격자)

### 4.1 핵심: 같은 물리 공간, 다른 격자 = 다른 좌표 대응
> 10m×10m를 200 cell로 나눌 때와 20m×20m를 100 cell로 나눌 때,
> **같은 인덱스가 가리키는 물리 좌표가 완전히 달라진다.**
- 모델 출력 격자와 GT 격자가 **같은 물리 좌표 → 같은 인덱스** 규칙을 공유해야 loss가 의미.
- 공유 안 되면 loss는 내려가도 학습이 틀림(조용한 실패).

### 4.2 Simple-BEV 특유의 강조점
- Simple-BEV는 **격자점을 이미지로 투영해 특징을 샘플**한다. 이 격자 정의(범위·해상도)는
  GT 정렬용일 뿐 아니라 **모델이 특징을 뽑는 좌표 그 자체**다.
- 격자가 GT와 안 맞으면: 모델은 X 위치 특징을 모으는데 GT는 Y를 정답이라 하는 **이중 어긋남**.

### 4.3 정렬할 4요소
GT(1024×1024 + bev_gt_meta)와 Simple-BEV 격자(`Vox_util`) 사이:
1. **커버 범위(미터):** GT 커버 범위 = Simple-BEV bounds(XMIN..XMAX, YMIN..YMAX).
2. **해상도/셀 크기:** GT를 모델 격자 해상도로 리샘플(예: 1024→200).
   - **nearest-neighbor 필수**(클래스 라벨 보간 금지).
3. **원점:** GT ego 원점 픽셀 ↔ 모델 격자 ego 원점 셀이 같은 물리점.
4. **축 방향:** GT 이미지 축 ↔ Simple-BEV BEV 축(+x 전방 등) 대응. 필요 시 GT flip/rotate/
   transpose.

### 4.4 Simple-BEV 격자 설정
- `utils/vox.py: Vox_util(Z, Y, X, scene_centroid, bounds, ...)`의 bounds/해상도를 찾아
  **GT 커버 범위와 일치**.
- 초기 권장: GT 커버 범위 채택, 학습 해상도 200×200 수준(1024는 과할 수 있음).
- **다운샘플 시 작은 장애물 손실** — occupied는 "존재하면 남기기"(max-pool 성격) 고려.

### 4.5 구현할 코드 (`verify_B_grid_alignment.py`)
- 입력: BEV GT, bev_gt_meta, Simple-BEV 격자 설정.
- 기능:
  1. GT를 모델 격자 범위·해상도로 리샘플(nearest) + drivable/occupied remap.
  2. 리샘플 GT 위에 ego 원점 마커 + 전방 화살표 오버레이.
  3. 물체 미터 좌표 → 격자 인덱스 환산 → 예상 셀 vs 실제 칠해진 셀 대조.
  4. 검증 A와 교차: 이미지 전방 벽이 리샘플 GT에서도 전방(모델 +x) 셀인가.
- 출력: 정렬 오버레이 + 좌표 대응 수치 리포트.

### 4.6 합격 기준
- 리샘플 GT에서 전방 물체가 모델 +x 셀에, 좌측 물체가 규약상 방향 셀에.
- "물체 미터 → 격자 인덱스" 환산값 = 실제 칠해진 셀.
- 검증 A와 방향 규약 무모순(이미지 전방 = GT 전방 = 모델 +x).

## 5. A·B 통합 교차검증 (권장)

한 샘플에서 A·B를 동시에 시각화해 세 좌표계가 하나로 꿰이는지 최종 확인.
```
[어안 이미지 + BEV 투영 오버레이]  +  [리샘플 GT + 원점/방향 마커]
→ 이미지 전방 벽이 양쪽에서 "전방"으로 일관되게 나타나는가.
```

## 7. 흔한 함정

- **라벨 리샘플 보간 금지**: 클래스 맵은 반드시 nearest-neighbor.
- **다운샘플로 작은 장애물 소실**: 1024→200 시 얇은 기둥/작은 물체 소실 가능. occupied는
  max-pool 성격(존재하면 남기기) 고려.
- **축 방향 혼동**: 이미지 좌표(row=아래 증가) ↔ BEV 물리(+x=전방)가 반대이기 쉬움.
- **ego 원점이 정중앙 아닐 수 있음**: BEV 카메라 장착 위치 확인.
- **BEV 카메라 어안 가능성**: top-down이어도 어안이면 주변부 스케일 비선형(6.2 확인).
- **native 격자 = 모델 투영 좌표**: 정렬 실패가 특히 치명적.

## 8. 미해결 / 확인 필요 (Phase 1에서 이어짐)

- BEV GT 실제 해상도(1024×1024 확정)와 커버 물리 범위.
- BEV 카메라 투영 모델(핀홀 vs 어안).
- ego 원점의 GT 픽셀 위치와 축 규약(CARLA ↔ Simple-BEV ↔ GT 이미지).
- Simple-BEV `Vox_util` 파라미터의 정확한 의미/기본값.
- 학습 해상도 선택과 작은 장애물 보존의 트레이드오프.
